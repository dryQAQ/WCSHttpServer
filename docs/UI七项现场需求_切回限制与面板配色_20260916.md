## 二、逐项实现

### ① 不允许切回终态波次（已完成/已取消）

**判定**：终态 = `WAVE_FINISHED(8)` / `WAVE_CANCELLED(6)`。
**仍可切回**：已下发(1) / 已绑定(2) / 分拣中(3) / 满箱同步(4) / 取消处理中(5) / 完结中(7) / 异常挂起(9)
（完结中必须可切回，否则失败 H8 无法续传）。

**三道防线**（顺序很重要）：

1. `HttpServer::resumeUnfinishedWave()` **入口守卫**（放在函数最前、**先于 `switchAwayCurrentWave()`**）：
   内存当前波次或 DB 状态为终态 → 只 `HTTP_LOG_WARN` + `emit logMessage` + `return false`，
   **不切出当前波次、不动绑定、不动任何内存结构**。
   > 为什么必须在最前：原实现在"校验1"里会先把当前波次切出去，若等到"校验2"才发现目标是终态，
   > 当前任务已经被切走了 —— "拒绝"这个动作本身产生了副作用。
2. 同会话快路径 / `switch(wave.status)` 的终态分支 → 改为**防御式拒绝**（若守卫被误删仍拒绝）。
3. `MainWindow::onResumeSelectedWave()` UI 守卫：在**摘要弹窗之前**判定 → 只打日志 + 刷新列表；
   列表状态列对终态行追加 `（不可切回）` 灰字标注 + 整行 tooltip；选中终态行时
   `m_btnResumeWave`（切换选中波次）自动禁用并提示改用「重传」。双击行走同一函数，限制一致。

**报文补发入口不受影响**：`重传满箱切换(H7)` / `重传任务完结(H8)` 读的是**波次表选中行**，
不依赖切回动作；终态波次的历史绑定与落格数据仍可通过 SQL/日志**只读回溯**（拒绝切回 ≠ 删数据）。

### ② 完全隐藏 66 格口（异常口）

- 隐藏对象 = **配置的物理异常口** `config.exceptionGrid`（现场 `= 66`），不写死数字；
  未配置（空 / `"0"`）时**不隐藏任何格口**（面板 66 格，与改造前一致，零回归）。
- `setupUI()` 建格循环：命中隐藏格 → `continue`（不建外框、不建标签、不入布局）；
  可见格按"可见序号"重排 `row/col`，隐藏后**不留空洞、行号不错位**；`m_bindingRows` 按可见数计算。
- `updateBindingPanel()` 循环首行再判一次（双保险），隐藏格不渲染、不计数。
- 计数口径：`未绑定 = 可见格口数 − 已绑定`（现场 `exceptionGrid=66` 时为 **65**）；
  `onStartStop()` 复位时也用同一口径（不再硬编码 66）。
- **后台行为不变**：66 号仍可被 H6 绑定（用于收集超计划件、人工清出），`grid_box_bind` /
  `sorting_records` 记录照旧，其 H7 早已在多处被跳过（异常口件不上传 WMS）。

### ③ 分拣记录查询：日期条件（必填区间）

- **口径**：区间**必须生效**（界面上没有"全部/不筛日期"选项）；默认起 = 今天 − 7 天、止 = 今天。
- **命中列** = `sorting_records.sort_time`（落格时间）；`>= '起日 00:00:00' AND <= '止日 23:59:59'`
  （含首含尾），字符串区间比较，走既有 `idx_sort_time` 索引。
- **待分拣（计划）行不受日期影响**：`return_wave_item` 没有落格时间，DB 层刻意**不加区间条件**，
  因此"计划 vs 实绩"对照不会因为筛选而丢行。
- 四种模式全部生效：
  - 按EPC（含留空查全部）：`queryByBarcode` / `queryAllWithPending` 的**已分拣部分**加区间；
  - 按SKU：`queryBySku` 加区间（计划明细不受影响，"待分拣"行照常显示）；
  - 按格口（含留空全格口汇总）：`queryByGrid` 与 `queryGridSummary` 加区间
    （汇总的计数 / SKU数 / 最近容器号 / 最近分拣时间都只反映区间内）；
  - 按容器号：`queryByBoxcode` 加区间，跨容器反查 `queryOtherBoxcodesByEpc` **同区间**
    （避免"结果被日期裁剪、反查却按全量"的口径打架）。
- 起 > 止 → 告警日志 + 自动对调后查询（不静默返回空）。
- 文案与日志：每个模式的统计标签、运行日志都带 `｜日期 a~b`；日期控件带口径 tooltip。
- **例外（有意保留）**：`showEpcDetail`（EPC 全信息窗）仍展示该 EPC 的**完整历史**，
  不受查询页日期区间约束 —— 那是"单件全生命周期排查"入口，按设计传空区间。

### ④ 开机：历史波次不占用格口绑定显示（根因修复）

**现场症状**：开机后格口绑定面板显示一堆箱号，看起来像"历史波次占用了绑定显示"。

**根因（实测证据）**：
- `release_WcsHttpServer/config/http_server.xml` 里存有 **43 条** `<binding grid="024">H-01-2024</binding>`
  之类的记录 —— 这是历史遗留镜像：`bindingUpdated` → `ConfigManager::save()` 会把**当时内存里的绑定**
  写回该 XML（一直在写）；
- 而 DB 侧 `grid_box_bind` 共 1718 行、`active=1` 为 **0** 行（绑定早已归档）；
- 原 `setupCore()` 有一条兜底："无未结束波次 + DB 无 active 绑定 → 采用 XML 预绑定"，
  于是这批残留 XML 被当成本次任务的绑定装载进了面板。

**修复**：**不再从 XML 装载任何绑定**。
- `setupCore()`：始终 `loadContainerBindings({})`（新任务状态）；同步 `cfg.containerBindings.clear()`
  （防旧值经随后的保存再写回文件）；日志明确记录"本次文件内 N 个已忽略"；
- `restoreWaveFromDB()`（开始接收时执行）：清内存 + 归档 DB `active` 行（只归档、不改归属），
  且**任何来源的绑定都不会在此被装载到界面**；
- 现行唯一来源：**本会话收到的 H6**，或**切回某个未结束波次**时按其记录恢复。
  XML 的 `<binding>` 视为历史镜像，**只写不读**（保留写入是为了不破坏既有落盘路径）。

### ⑤ 一键满箱回传旁的三项计数

界面：`[一键满箱回传]  本波次满箱回传 N 次（成功x/待发y/失败z） ｜ 本次一键 成功 A / 失败 B`

| 数字 | 口径 | 来源 |
| --- | --- | --- |
| 本波次满箱回传 | 当前波次**已生成的 H7 报文总数**（含自动满箱、手动满箱、一键回传），括号内为成功/待发/失败拆分 | `getFullboxStatusCountAll()`（既有批量接口，`outbox_fullbox` 一行 = 一个报文） |
| 本次一键 成功 | 本次「一键满箱回传」**成功生成并入 Outbox** 的报文件数（会话累计，切波次归零） | `manualFullbox()` 返回值（msgId 非空） |
| 本次一键 失败 | ① 本次**未能生成报文**（Outbox 写入失败 / 无容器 / 缺SKU / 异常口等）＋ ② 本次生成的报文**最终重试耗尽失败**的件数 | 失败原因 + `fullboxMessageFailed` 信号（按 msgId 归因） |

- **"格口无分拣记录跳过"不计入失败**（沿用既有日志口径）：`manualFullbox()` 返回空串时按原因区分，
  只有"无待上传的分拣记录"计入跳过数，其余原因计入失败。
- 归因机制：一键生成的每个 msgId 记入 `m_oneKeyMsgIds`；`HttpServer::onFullboxReplyFinished()`
  在"重试耗尽 → status='failed'"处 `emit fullboxMessageFailed(msgId, order, grid)`，
  UI 只对**命中集合**的 msgId 计失败（自动满箱/手动重传的失败不会污染"本次一键"数字）。
- 刷新时机（**不每秒查库**）：初始化 / 一键开始与结束 / 启停接收 / **波次变化检测**（复用定时器里
  既有的 `lastTraceOrder` 比较）/ 失败回执。波次变化时"本次"归零并清空 msgId 集合
  （迟到回执不会误计到新波次）。
- 失败数 > 0 时标签整条标红；日志追加一行同源计数（`[一键满箱] 计数：…`）。
- 动作语义不变：不动波次状态机、不禁用格口、不改容器绑定、异常口照旧跳过；热点路径零重构
  （`sendFullboxForGrid` 逻辑不变，只把返回值升级为 msgId，`bool` 版本是它的薄封装）。

### ⑥ H7 失败下拉只显示本波次

- 新增 `SortingDatabase::getFailedOutboxFullboxByOrder(orderCode, limit)`：口径与原来完全一致
  （`status IN ('failed','cancelled')`），只多一个 `order_code` 条件；
  原"全部历史"版本 `getFailedOutboxFullbox()` 随之失去调用方，**已删除**（不留死代码）。
- `HttpServer::getFailedFullboxItemsByOrder()`：把原聚合循环抽成 `aggregateFailedFullbox()`，
  按 `(波次, 格口)` 聚合、`failCount`、failed/cancelled 混合标 `mixed`、老数据 grid 从 payload 反解 —— 口径不变。
- UI：下拉内容 = 当前运行波次的失败/已取消 H7；无失败 → `本波次暂无失败记录`；
  无运行波次 → `暂无运行波次`（两者都会清空可编辑框便于手输格口）。
- **H8 下拉保持"全部历史失败波次"**：需求只要求 H7；否则"已完成波次补发 H8"的入口会断
  （且本方案已禁止切回终态波次）。
- 三条重传分支逻辑不变：精确补发（按格口）/ 手输格口（仍可任意格口）/ 下拉为空时按**波次表选中行**
  或当前波次整波次补发。

### ⑦ 整格底色 = 绑定状态 + 去掉圆点 + 字号调大

| 面板状态 | 底色 | 文字色 | 格口面板内容 |
| --- | --- | --- | --- |
| 已绑定（有容器，未锁格未禁用） | **绿 `#26A96C`** | 白 `#FFFFFF` | 箱号 |
| 满箱锁格（S7 物理锁格位） | **橙 `#F37021`** | 白 | `锁格`（无箱号时）或箱号 |
| 已解锁·待重绑（等 WMS 发 H6） | **红 `#994444`** | 白 | `待重绑`（无箱号时）或箱号 |
| **未绑定** | **不设颜色**（无色 = 默认状态） | **深灰 `#333333`** | `--` |

- **未绑定为什么必须用深灰字**：该状态不设背景色，格子透出面板默认底色（浅色），
  白字在浅底上不可读 —— 因此文字色随状态取（`bpBoxTextColorOf()`），自测已锁定这条口径。
- **字号调大（本次）**：格口号 11px → **13px**；箱号/状态文字 11px → **13px**（状态圆点仍隐藏）。
- 优先级（同格多状态并存时）：**锁格 > 待重绑 > 已绑定 > 未绑定** —— 由 `bpStateOf()` 单点决定。
- 实现：外框 `QFrame` 承载底色（子标签均声明 `background: transparent`，底色正常透出）；
  有色态样式 = `background + border`，无色态样式 = `border`（`BP_FRAME_STYLE_PLAIN`）；
  状态圆点对象保留但 `setVisible(false)`；建格时初始 = 未绑定（无色），与开机新任务状态一致。
- 图例改为：`■绿色=已绑定  ■橙色=满箱锁格  ■红色=已解锁·待重绑  未绑定=无底色（默认）`
  （未绑定不再显示色块）+ tooltip 说明优先级与隐藏规则。
- `onStartStop()` 复位：外框回无色、箱号文字回深灰、字号保持 13px、计数一起复位。
- **口径唯一来源**：`tests/BindingPanelPolicy.h` 的纯函数（`bpStateOf` / `bpColorOf` / `bpBoxTextOf` /
  `bpBoxTextColorOf` / `bpIsGridHidden` / `bpVisibleSlotCount` / `bpFrameStyle`），
  产品侧 `MainWindow` 与自测 `tests/test_binding_panel_policy.cpp` **共用同一实现** ——
  配色/优先级/文字色被改坏会立刻被自测抓住（含"未绑定样式不得含 background""不得残留旧灰 `#7A7A7A`"两条硬断言）。

- 按钮在「**任务接收控制**」区，与「查看接收波次队列」「设置配置」**同一水平行**，

```
│ │                                     │ │ 本次累计    58,300 件 │
│ │ [清空日志]                          │ │ [最近30分钟][今日0~23点] │
│ └─────────────────────────────────────┘ │   ┌── 柱状/折线图 ──┐  │
└────────────────────────────────────────────────────────────────┘

（任务接收控制区同一行：  [查看接收波次队列] [效率统计(按下)] [设置配置] ）
```

- 四个数字的口径（**全部复用既有实现，不新增统计逻辑**，避免出现两套口径）：
  | 数字 | 含义 | 来源 |
  | --- | --- | --- |
  | 当前(1分钟) | 滑动 60 秒窗口内的 RFID 推送件数（折算件/时） | `rfidPushPerMinute()` |
  | 当日峰值 | 当日 1 分钟窗口最高件数（折算件/时）；跨日自动重置并落库 `daily_peak` | `peakPerMinuteToday()` |
  | 本小时累计 | 本小时各分钟桶之和（当日观察口径） | `efficiencySeries(1440)` + `sumMinuteBucketsOfHour()` |
  | 本次累计 | 程序启动至今累计推送件数（跨波次不清零） | `rfidPushTotal()` |
- 趋势图用**按钮切换**（`最近30分钟` 柱状 / `今日0~23点` 折线），而不是上下叠两张：
  右侧是窄栏，叠两张会被压扁看不清。切换后立即重绘。
- **按需懒创建**：面板首次显示时才 `new`（那时 `setupCore()` 已建好 `HttpServer`，
  不会出现"面板已建但统计源还是空指针"的瞬间）；之后复用同一实例（不重建控件、不丢图类型切换状态）。
- **刷新策略（性能关键）**：
  - 由主界面既有的 **1 秒刷新定时器**驱动，但面板**不可见时（按钮弹起 / 切到别的标签页）
    `tick()` 直接返回**，不查询、不重绘 —— 看日志不会拖慢分拣；
  - 数据量有界：最近 30 分钟 = 30 点；当日分钟桶 ≤ 1440 点；QCustomPlot 自带缓冲与
    `rpQueuedReplot`（合并重绘请求）；
  - 一次 `efficiencySeries()` 调用同时取"分钟桶 + 小时峰值"（同一次加锁，不会读到两个瞬间）。
- 面板宽度可拖（默认约 340px，最小 280px），日志区始终吃满余量；点「清空日志」不影响本面板。
  > ★ 2026-09-17 现场口径变更：**日志区与效率统计面板改为各占一半宽**（初始 50%/50%，两侧 stretch 同为 1），
  > 最小宽度 280px 与可拖动行为保留。详见 `docs/UI四项现场需求_日志分栏与页面开关_20260917.md`。
- 已知边界：`HttpServer` 在 `setupCore()` 创建，而按钮的"默认开启"状态在 `setupUI()` 就已设置，
  因此构造函数在 `setupCore()` 之后**显式应用一次** `applyLogEffPanelVisible(true)`
  （否则面板要等用户点一次才出现）。`setChecked()` 不会发出 `toggled` 信号，故这一步是必需的。
- 自动自测覆盖：本面板的四个数字全部来自**已被自测覆盖的既有接口**；"按小时归并"是唯一的派生计算
  （纯函数 `sumMinuteBucketsOfHour`，逻辑为"按桶时间戳取小时并求和"），未单独建用例
  （属展示层计算，且不涉及状态/数据契约）。

## 三、验收步骤（现场照做）

1. **需求④**：`config/http_server.xml` 现存 43 条 `<binding>` → 直接启动程序 →
   绑定面板**全为未绑定（无底色）**；运行日志出现
   `[容器绑定] 启动为新任务状态：不装载 XML 绑定（本次文件内 43 个已忽略）…`。
2. **需求①**：在「波次数据历史记录」选中一条 `已完成` 或 `已取消` 的行 →
   状态列显示 `已完成（不可切回）`，「切换选中波次」按钮变灰；双击/点击 →
   只有 `[切换] 波次 … 已完成/已取消：按需求不允许切回…`，
   **不再出现** `[切换] 已保存并切出波次…`（当前运行波次未被切出）。
3. **需求②**：面板显示 **65** 个格口、无 66 号；`已绑定 + 已锁格 + 未绑定 = 65`；
   66 号在「按格口查询」与落格明细里仍可查（仅界面不显示）。
4. **需求⑦**：逐格核对底色 —— 已绑定格为新绿 `#26A96C` + 白字；**未绑定格无底色**（面板默认色）+ **深灰字**；
   锁格橙、待重绑红；圆点已消失；格口号与箱号**字体明显变大（13px）**；
   图例为 `■绿=已绑定 ■橙=满箱锁格 ■红=已解锁·待重绑  未绑定=无底色（默认）`；
   点「结束任务」后整面板回到无色 + `--` + `未绑定: 65`。
   同一页顺带核对**需求⑧**：波次信息面板的「状态」为白字色块 ——
   分拣中应为橙、完结中/异常挂起应为红、已完成/已取消应为灰、空闲应为灰、已绑定应为绿、已下发应为蓝。
5. **需求③**：按EPC/按SKU/按格口/按容器号四种模式各查一次：
   结果只含所选日期区间内的落格记录，统计标签与日志都带 `日期 a~b`；
   把起止设为无数据的日期 → 返回 0 条；SKU 模式下「待分拣」行仍在。
6. **需求⑤**：点一次「一键满箱回传」→ 「本次一键 成功」增加量 = 本次新增报文数
   （无分拣记录的格口跳过、不计入成功也不计入失败）；标签与日志同步刷新；
   断网制造失败 → 该报文重试耗尽后「本次一键 失败」+1。
7. **需求⑥**：当前波次无失败时下拉显示 `本波次暂无失败记录`，且**不含**其它波次的失败；
   停止接收后显示 `暂无运行波次`；有本波次失败时只列本波次格口，点按钮仍能精确补发。
8. **需求⑨ + 按钮移位**：
   - 「分拣记录查询」页的条件行里**已无**「效率统计」按钮（查询/清空等控件不受影响）；
   - 「任务接收控制」区该行顺序为 `[查看接收波次队列] [效率统计] [设置配置]`（效率统计在设置配置左侧）；
   - 程序启动后「效率统计」按钮应为**按下态**，切到「运行日志」页 → 右侧已显示效率面板，
     四个数字随推送实时变化（上料时"当前(1分钟)"随节奏跳动）；
   - 点 `今日0~23点` 切换到小时折线、点 `最近30分钟` 切回柱状；
   - 再点「效率统计」→ 面板隐藏、日志吃满宽度、按钮弹起；再点 → 重新显示并立即出数；
   - 面板显示时切到其它标签页再回来 → 数据立即刷新（不可见期间不刷新，属设计如此：避免后台空转）；
   - 拖动中间分隔条可调宽度，日志区与面板互不遮挡。
9. 只读 SQL 核对（不改数据）：
   ```sql
   -- 需求⑤ 计数来源（本波次满箱回传次数 = 该波次行数）
   SELECT order_code, status, COUNT(*) FROM outbox_fullbox GROUP BY order_code, status;
   -- 需求④：启动后"当前活跃绑定"应为空（历史行仍在，仅 active=0）
   SELECT grid_num, boxcode, order_code, active FROM grid_box_bind WHERE active = 1;
   -- 需求⑥：本波次失败 H7（应只出现在当前波次的行里）
   SELECT order_code, grid, status, COUNT(*) FROM outbox_fullbox
     WHERE status IN ('failed','cancelled') GROUP BY order_code, grid, status;
   ```
10. 截图留档（程序运行时执行）：`python test/ui_layout_probe.py`
    —— Win32 枚举读不到 Qt 控件，**只出截图供人工核对**底色/文字色/字号/图例/效率面板，不作自动判定。

## 四、已知边界与取舍

- **终态波次不再有"载入查看"**：切回被拒是需求要求；数据不删除，失败报文用「重传」按钮补发，
  历史仍可 SQL/日志只读回溯。
- **需求③ 没有"不筛日期"入口**：这是客户明确口径；需要看更早数据时把起止日期往前放宽即可。
- **跨容器反查与主查询同区间**：因此只查"今天"时不会报出"昨天落过的另一个箱"；
  做跨天漂移核对时把起始日期放宽到覆盖历史即可（自测用例已锁定该行为）。
- **EPC 全信息窗不受日期区间约束**：单件全生命周期排查入口，按设计展示完整历史。
- **未绑定不用任何底色**（客户最终口径）：`#B8A060`（金黄）与 `#7A7A7A`（灰）两个中间版本都已作废，
  未绑定 = **不设背景**（面板默认底色透出）+ **深灰字 `#333333`**。
  若现场日后想给未绑定额外一个底色，改 `tests/BindingPanelPolicy.h` 的 `BP_COLOR_UNBOUND` 一行即可
  （自测会同步校验"未绑定样式含/不含 background"与文字色）。
- **H8 下拉未按波次过滤**：需求只提 H7；H8 保持"全部历史失败波次"，以保留已完成波次的补发入口。
- **一键"失败"不含异步瞬时失败**：报文只要成功入 Outbox 就计"成功"（后续由重试机制兜底），
  只有"重试耗尽"才计失败 —— 与既有 H7 失败判定口径完全一致。
- **XML `<binding>` 只写不读**：现场若有人手工预置绑定，该预置自本次起不生效（日志会明确告知）；
  预置绑定请改由 WMS 下发 H6，或切回某个未结束波次恢复。
