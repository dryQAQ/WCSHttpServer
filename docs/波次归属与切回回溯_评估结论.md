# 波次归属标签评估结论：切回/回溯进度与状态是否需要"加波次号"

> 版本：2026-09-15
> 评估起因：讨论"是否给每个波次任务的相关数据在数据层加 `order_code` 标签"
> 最终口径（客户确认）：**只要不影响主要工作流与运行性能，就不强行加波次号**；
> 加波次号的初衷是**保护"切换/回溯波次任务"的进度与相关信息状态的保留**。
> 结论：**该目的现设计已达成，未新增波次号标签**。
> 
> ★ 2026-09-15 后续落地（同一结论下的实现调整，不改数据结构）：
> ① 需求②"RFID 原始报文留痕"已实现，新增只读表 `rfid_raw`（**按 EPC/时间索引，默认不加波次列**，
>    与本文 §2 的判断一致）；
> ② 需求①"每次关闭切出波次 + 开启新任务清空格口绑定 + 切回恢复绑定"已实现，
>    做法是**复用 `grid_box_bind` 既有的 `order_code` + `active` + 时间列**（绑定只追加不删除，
>    关闭时归档 `active=0`、切回时按波次取回），**未改表结构、未加索引、未加波次号标签**。
>    实现口径见 `docs/意外关闭重启_继续上次任务.md`。
>
> ★ 2026-09-16 断电路径核对与补齐（仍**未改表结构、未加波次号**）：
> 设备断电（异常关闭）→ 次日开机（新任务状态）→ 切回昨晚波次，逐格绑定状态完好；
> 补齐两处：① 切回时"已落格进度"按 `sorting_records` 重建（此前 `getLandingRecordsForWave()`
> **无调用者**，属"文档声称已做、代码未接线"）；② H6 归属为空时绑定行以 `order_code=''`
> 保留（原先绑 NULL 触发 `NOT NULL` 约束 → **整行插入失败**）。详见同文档 §3.6/§3.8/§3.9。
>
> ★★ 2026-09-17 结论更正（现场取证）：**上文"切回/回溯所需数据已全部保护"的结论与现场事实不符**，
> 根因不在表结构（`grid_box_bind` 本就带 `order_code`），而在**写入路径与取数口径**：
> ① 归属为空时绑 NULL 的历史缺陷在**现场 exe 里仍生效**（09-17 04:28 有 93 条
>    `NOT NULL constraint failed: grid_box_bind.order_code`）→ **整行丢失**，该波次零绑定；
> ② 120s"切出窗口归属"会把**下一个波次的 H6 记到刚切出的上一个波次**
>    （09-15 23:53 的 66 行实为 `456456` 的绑定，却挂在 `6565656` 名下）；
> ③ 切回主口径"每格全表最后一条属本波次"实测 14 个历史波次里 13 个返回 0 行，
>    且部分命中时会整体替换内存绑定 → 面板被清空。
> 修复（**仍不改表结构、不加波次号冗余列、不建快照表**）：H4 到达时**归属补齐/纠偏**
> （只改 `order_code`、不增删行）+ 切回改以"本波次自己的记录"为主口径 + 列表「格口绑定」列与
> 「查看绑定」只读弹窗。详见 `docs/格口绑定波次归属_根因与修复_20260917.md`。
> —— 这也印证了本文 §2 的判断：**不需要给这批数据加波次号**；缺的是"写入时归属别丢/别错"。

## 一、结论

**切回（resume）与回溯（trace-back）所需的进度与状态，现有设计已全部带波次归属（`order_code`），或可由带归属的数据推导出来 —— 不需要为"保护切回"新增任何波次号。**

唯一没有波次列的是 RFID 原始帧留痕表 `rfid_raw`，它**只读、不参与任何恢复或业务判定**，
回溯用 EPC/时间即可 → 按"不强行加"的原则**默认不加**（如日后要"按波次一键取证"，再加一行 ALTER + 索引，不影响主流程）。

## 二、逐项核对（切回/回溯需要什么 × 现设计是否保护）

| 切回/回溯需要的数据                | 现设计来源                                                             | 波次归属              | 结论                                                                     |
| ------------------------- | ----------------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------- |
| 波次头（波次号/件数/状态）            | `return_wave`（主键 = order_code）                                    | ✅ 主键              | 已保护                                                                    |
| SKU→格口映射 + 每格口计划件数        | `return_wave_item.order_code` + `idx_wave_item_order`             | ✅                 | 已保护                                                                    |
| 已分拣 EPC 集合（进度、防重、重复下发拦截）  | `sorting_records.order_code` + `idx_order_code`                   | ✅                 | 已保护                                                                    |
| 未闭环异常集合（面板「处理/异常口」件数）     | `exception_record.order_code`                                     | ✅（无索引，仅影响按波次查询速度） | 已保护                                                                    |
| 已落格明细（H7 报文明细源、超计划封顶依据）   | `sorting_records`（含 grid_num / boxcode / sku / volu / sort_time）  | ✅                 | 已保护（`getLandingRecordsForWave` 按波次正序取，切回时据此补齐）                         |
| 计划额度 / 封顶计数 / 落格明细去重集合    | 内存结构，切回时按 `sorting_records` 重建                                    | ✅ 可推导             | 已保护                                                                    |
| 格口容器绑定（切回时恢复绑定 / 回溯时期看历史） | `grid_box_bind.order_code` + `active` + `bind_time`/`unbind_time` | ✅                 | **★ 2026-09-17 更正**：列本身够用，但归属**依赖 H6 时刻的内存波次**（H6 报文不含波次号），曾出现"整行丢失 / 记到上一个波次 / 切回被清空"；现已由 H4 到达时的**归属补齐/纠偏**兜底，切回改以"本波次自己的记录"为主口径（`getBindsByOrder`），并新增列表「格口绑定」列与「查看绑定」只读弹窗 |
| H7/H8 未成功报文（切回自动补发）       | `outbox_fullbox`（`idx_outbox_order`）/ `outbox_end`（无索引）           | ✅                 | 已保护                                                                    |
| H4 原始报文（WMS 下发波次原文）       | `wave_raw`（主键 = order_code）                                       | ✅                 | 已保护                                                                    |
| 完结波次归档快照                  | `wave_history.db`（按波次快照）                                          | ✅                 | 已保护                                                                    |
| 日峰值效率统计                   | `daily_peak`（按日期）                                                 | ❌（设计如此，与波次无关）     | 无需波次                                                                   |
| RFID 原始帧（只读留痕）            | `rfid_raw`（按 EPC / epc_raw / 时间 索引）                               | ❌ 无波次列            | **不影响切回/回溯**：按 EPC 或时间即可查；不参与恢复与判定                                     |

**关键论据**：切回/回溯需要的数据，要么**已在数据库且带 `order_code`**，要么**可由带 `order_code` 的数据推导**。
因此"给这批数据再加波次号"对保护切回进度**没有额外收益**；反过来，现有实现里"切回时从 DB 重建"
（`resumeUnfinishedWave` 步骤 3/4/6/7）正是这条推导链的落地。

**绑定为什么"归档了还能切回恢复"**：`grid_box_bind` 只追加不删除，归档只把 `active` 置 0 并写 `unbind_time`；
切回取数口径 = 每格在全表中最后一条记录且该记录属于本波次、容器号非空（**不按 `active` 过滤**）。
所以"新任务开始时清空绑定关系"与"切回时恢复该波次绑定"由同一张表同时满足，无需新增任何列。

## 三、两个与"波次号"无关的已知边界（仅备忘，不在本次改动）

### 3.1 在途（已下发、未收到落格反馈）状态不持久化

- 现象：重启后该件若再被 RFID 读到，会**重新下发一次** PLC 指令（在途集合是内存态）。
- 影响界定：**不会重复计件**——落格明细去重集合、已分拣集合、计划额度都在切回时按 DB 重建，(格口,EPC) 与 (波次,EPC) 两级去重生效；同一物理件仍只算 1 件、H7 明细也只记 1 条。
- 若现场明确要求"重启后不重发在途件"，才需要把在途集合落库（属**新增写入路径**，当前判断：不需要）。

### 3.2 历史库存在重复落格明细（仅历史数据）

- 实测：`release_WcsHttpServer/data/sorting_records.db` 中 `(order_code, grid_num, barcode)` 计数 > 1 的有 **13 组**
  （例：`WAVE-20260817-001` 的 `epc001@001` 有 7 条；`PP202600000039` 多件各 2 条）。
- 成因：09-14 之前落格明细只靠"每次写入都新增"，重复反馈/换箱前后会写两条 —— 这正是 09-13/09-14「箱内实落对不上、WMS 整条驳回」的同类根因。
- 现状：**新数据已被拦住**（09-14 内存去重 + 本轮"切回时把去重集合按 DB 重建"），所以不会新增重复；历史 13 组仅影响"回溯对账时的真实性"。
- 处置：默认**只报告、不改数据、不加约束**；核对方式见 `docs/dup_landing_report.py`（只读脚本）。

## 四、明确"不改动"清单（保证主流程与性能零影响）

- 不动数据库结构、不加索引（`exception_record` / `outbox_end` / `grid_box_bind` 的 `order_code` 索引本次不补）。
- 不动内存结构的键（不加波次前缀）、不动 RFID→PLC→落库热路径。
- 不新增数据库写入（在途集合、去重集合一律保持"从 DB 推导"）。
- 不建唯一约束、不修改历史数据。
- 本文档对应的评估结论本身未改产品代码；后续 09-15 的两个需求实现（`rfid_raw` 新表、绑定归档/切回恢复）
  同样**未加波次号标签、未改既有表结构**，仅新增了 3 条只读 SQL 与对应接口。

## 五、触发条件备忘（何时才值得再做波次标签/索引）

| 触发条件                        | 届时动作（增量小、零行为变化）                                                                                          |
| --------------------------- | -------------------------------------------------------------------------------------------------------- |
| 单表 > 5 万行且"按波次查询"耗时 > 100ms | 补 3 条索引：`exception_record(order_code)`、`outbox_end(order_code)`、`grid_box_bind(order_code, active)`      |
| 现场提出"按波次一键取证（含原始帧）"         | `rfid_raw` 加 `order_code` 列 + 索引；新数据带当前波次、历史行留空（不猜测回填）                                                   |
| 新数据再次出现重复落格明细               | 才谈 `UNIQUE(order_code, grid_num, barcode)` 或接线 `sort_txn`（其 `(order_code, epc)` 唯一索引已存在但未接线）；需先按报告去重历史数据 |

## 六、现场可核对清单（不改代码，纯 SQL）

```sql
-- ① 波次头（是否存在、状态、件数）
SELECT order_code, order_qty, status, created_at, updated_at FROM return_wave WHERE order_code = '<波次号>';
-- ② SKU→格口计划
SELECT inco, grid_num, grid_type, plan_qty FROM return_wave_item WHERE order_code = '<波次号>';
-- ③ 已落格明细（进度/H7 报文源）
SELECT id, barcode, sku, grid_num, boxcode, sort_time FROM sorting_records WHERE order_code = '<波次号>' ORDER BY id;
-- ④ 异常留痕
SELECT id, type, epc, sku, handled, time FROM exception_record WHERE order_code = '<波次号>' ORDER BY id;
-- ⑤ 容器绑定（含来源波次与是否活跃）
SELECT grid_num, boxcode, order_code, active, bind_time, unbind_time FROM grid_box_bind WHERE order_code = '<波次号>' ORDER BY grid_num;
-- ⑥ H7/H8 出站报文
SELECT msg_id, order_code, grid, boxcode, status, retry_count FROM outbox_fullbox WHERE order_code = '<波次号>';
SELECT msg_id, order_code, status, retry_count FROM outbox_end      WHERE order_code = '<波次号>';
-- ⑦ H4 原始报文
SELECT order_code, length(raw_body) FROM wave_raw WHERE order_code = '<波次号>';
-- ⑧ 重复落格明细自查（应无输出；有输出则见 §3.2）
SELECT order_code, grid_num, barcode, COUNT(*) c FROM sorting_records
 WHERE barcode <> '' GROUP BY order_code, grid_num, barcode HAVING c > 1 ORDER BY c DESC;
-- ⑨ ★ 2026-09-15 关闭切出后：该波次绑定应全部 active=0 且 unbind_time 有值（行不删除，可回溯）
SELECT grid_num, boxcode, active, bind_time, unbind_time FROM grid_box_bind
 WHERE order_code = '<波次号>' ORDER BY CAST(grid_num AS INTEGER), id;
-- ⑩ ★ 2026-09-15 启动后"当前活跃绑定"应为空（新任务状态）
SELECT grid_num, boxcode, order_code FROM grid_box_bind WHERE active = 1;
-- ⑪ ★ 2026-09-15 RFID 原始报文（识别前后都能命中；同一 EPC 多行 = 双读/重扫重投）
SELECT time, epc, epc_raw, seq, car_num, raw_frame FROM rfid_raw
 WHERE epc = '<EPC>' OR epc_raw = '<EPC原文>' ORDER BY id DESC LIMIT 50;
-- ⑫ ★ 2026-09-17 切回恢复口径（= UI「格口绑定」列与「查看绑定」弹窗的同一 SQL）：
--    每格取“本波次内”最后一条绑定；该波次切回时恢复的就是这些格口
SELECT g1.grid_num, g1.boxcode, g1.active, g1.bind_time, g1.unbind_time
  FROM grid_box_bind g1
 WHERE g1.order_code = '<波次号>' AND g1.boxcode <> ''
   AND g1.rowid = (SELECT MAX(g2.rowid) FROM grid_box_bind g2
                    WHERE g2.grid_num = g1.grid_num AND g2.order_code = '<波次号>')
 ORDER BY CAST(g1.grid_num AS INTEGER);
-- ⑬ ★ 2026-09-17 该波次“有没有绑定记录”（0 = 切回恢复不出绑定 → 列表红字「无绑定记录」）
SELECT COUNT(DISTINCT grid_num) FROM grid_box_bind
 WHERE order_code = '<波次号>' AND boxcode <> '';
-- ⑭ ★ 2026-09-17 归属补齐/纠偏审计（本会话内被改判的行；候选行明细见 data.log）
SELECT id, grid_num, boxcode, order_code, bind_time FROM grid_box_bind
 WHERE order_code = '<波次号>' AND bind_time >= '<本次程序启动时刻>' ORDER BY id;
```
