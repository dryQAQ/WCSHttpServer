## 一、需求分解

### 1.1 业务背景

WMS（仓库管理系统）向 WCS 发送取消当前波次任务的指令。WCS 接收到取消指令后，清空当前波次的所有数据（格口映射、分拣状态、异常记录），恢复到空闲状态，等待下一个波次。

### 1.2 功能分解

| 序号 | 子功能 | 说明 | 优先级 |
|------|--------|------|--------|
| 1 | 新增 API 路由 | POST `/api/DispatchSortingCommand/CancelWaveInfo` | P0 |
| 2 | 参数校验 | 校验 `orderCode` 非空、波次号匹配 | P0 |
| 3 | 状态保护 | 仅允许 `WAVE_RECEIVED` 状态取消，`WAVE_SORTING` 拒绝 | P0 |
| 4 | 数据清理 | 调用 `WaveManager::clearWave()` 清空所有状态 | P0 |
| 5 | GridBuffer 清理 | 替换格口映射为空 Map | P0 |
| 6 | 日志记录 | 记录取消操作和结果 | P1 |

### 1.3 涉及文件

| 文件 | 改动类型 | 代码行数 |
|------|----------|----------|
| `HttpServer.h` | 新增声明 | +1 行 |
| `HttpServer.cpp` | 新增路由 + 处理函数 | +28 行 |
| **总计** | | **~30 行** |

> **说明**: `WaveManager::clearWave()` 已完整实现，无需修改。GridBuffer 的清理通过 `DoubleBuffer::prepareSwap()` 完成，也无需修改。

### 4.3 HttpServer.cpp — 新增 handleCancelWaveInfo 处理函数

```cpp
// 位置: 第 406 行之后（handleWaveStatus() 函数之后）

QJsonObject HttpServer::handleCancelWaveInfo(const QJsonObject& req)
{
    QString orderCode = req["orderCode"].toString().trimmed();
    if (orderCode.isEmpty()) {
        HTTP_WARN("取消波次 缺少orderCode字段");
        emit logMessage("[取消] 缺少orderCode字段", true);
        return errResponse("缺少orderCode字段");
    }
    if (m_pWaveMgr->orderCode() != orderCode) {
        HTTP_WARN("取消波次 波次号不匹配 req=%s current=%s",
            orderCode.toLocal8Bit().data(),
            m_pWaveMgr->orderCode().toLocal8Bit().data());
        emit logMessage(QString("[取消] 波次号不匹配 req=%1 current=%2")
            .arg(orderCode).arg(m_pWaveMgr->orderCode()), true);
        return errResponse("波次号不匹配");
    }
    if (m_pWaveMgr->status() == WAVE_SORTING) {
        HTTP_WARN("取消波次 分拣已开始，不允许取消 orderCode=%s",
            orderCode.toLocal8Bit().data());
        emit logMessage(QString("[取消] 分拣已开始，不允许取消 %1").arg(orderCode), true);
        return errResponse("分拣已开始，不允许取消");
    }
    m_pWaveMgr->clearWave();
    HTTP_INFO("波次取消成功 orderCode=%s", orderCode.toLocal8Bit().data());
    emit logMessage(QString("[取消] 波次取消成功 %1").arg(orderCode));
    return okResponse("波次取消成功");
}
```

## 六、业务规则说明

### 6.1 核心规则

| 规则编号 | 规则描述 | 实现方式 |
|----------|----------|----------|
| **R1** | 仅 `WAVE_RECEIVED` 状态允许取消 | 检查 `m_pWaveMgr->status() == WAVE_SORTING` → 拒绝 |
| **R2** | `WAVE_SORTING` 后不允许取消 | 分拣已开始，数据完整性保护 |
| **R3** | 取消后状态变为 `WAVE_CLEANED` | `clearWave()` → `setState(WAVE_CLEANED)` |
| **R4** | 取消操作同时清空 GridBuffer | 预留，`clearWave()` 不直接操作 GridBuffer |
| **R5** | 波次号必须匹配 | 校验 `m_pWaveMgr->orderCode() != orderCode` |
| **R6** | `orderCode` 不能为空 | 校验 `orderCode.isEmpty()` |

### 6.2 状态约束详解

```
允许取消的状态:
  WAVE_RECEIVED (1)  — 波次已接收，但尚未有任何分拣操作
                       → clearWave() → WAVE_CLEANED

拒绝取消的状态:
  WAVE_IDLE (0)       — 无波次，取消无意义
  WAVE_SORTING (2)    — 分拣已开始，存在在途包裹，数据完整性风险
  WAVE_COMPLETING (3) — 回传进行中，WMS 正在接收数据
  WAVE_CLEANED (4)    — 波次已结束，无需取消
  WAVE_ERROR (5)      — 异常状态，应通过管理手段处理
```

### 6.3 clearWave() 清理内容详解

```cpp
void WaveManager::clearWave()
{
    std::unique_lock<std::mutex> lock(m_lock);
    m_setCodeRecv.clear();       // 清空接收到的 inco 集合
    m_setCodeSorted.clear();     // 清空已分拣 inco 集合
    m_setCodeException.clear();  // 清空异常 inco 集合
    m_mapCodeRetry.clear();      // 清空重试计数
    m_setCodeProcessing.clear(); // 清空处理中 inco 集合
    m_orderCode.clear();         // 清空波次号
    m_orderQty = 0;              // 重置波次件数
    m_bSortingStarted = false;   // 重置分拣开始标志
    m_bReported.store(false);    // 重置回传标志
    setState(WAVE_CLEANED);      // 状态机 → CLEANED
}
```

### 6.4 线程安全保证

- `clearWave()` 内部使用 `std::unique_lock<std::mutex>` 保护所有集合操作
- `m_bReported` 使用 `std::atomic<bool>` 保证原子性
- `setState()` 内部使用 `std::atomic<int>` 的 `store/load`
- HP-Socket 请求在业务线程池中异步处理，不阻塞 I/O 线程
- `SendResponse` 在 HP-Socket 中是线程安全的
