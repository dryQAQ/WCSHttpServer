# WCS_httpServer 三大功能接口封装方案

> 向主管汇报用 | 接口一: 退货任务格口分配 / 接口二: 格口容器绑定 / 接口三: 退货任务取消

---

## 一、总览：统一封装模式

三个 WMS → WCS 接口均遵循同一封装模式，核心路径为：

```
HP-Socket 回调 → OnMessageComplete → commitNoWait(业务线程池) → processRequest(路由) → handleXxx(业务)
```

```
  HTTP 请求到达
      │
      ▼
  OnRequestLine() → 解析 method/path         (HP-Socket I/O 线程, <1μs)
      │
      ▼
  OnBody() → 累积 body 到 ConnState          (HP-Socket I/O 线程, <1μs)
      │
      ▼
  OnMessageComplete()                         (HP-Socket I/O 线程)
      │
      ├── 取出 ConnState（拷贝）
      ├── commitNoWait(lambda)               ← 异步 offload 到业务线程池
      └── 立即返回 HPR_OK                    (不阻塞 I/O, <1ms)

  ┌─────────────────────────────────────────┐
  │  业务线程池 (64 threads)                 │
  │  processRequest(pSender, dwConnID, st)  │
  │      │                                   │
  │      ├── 路由1: InsertWaveInfo           │
  │      ├── 路由8: BindingLatticePort       │
  │      └── 路由9: CancelWave               │
  └──────────────┬──────────────────────────┘
                 │
                 ▼
  sendJsonResponse() → HP-Socket SendResponse (线程安全)
```

## 二、接口一：退货任务格口分配

### 2.1 路由入口

```cpp
// HttpServer.cpp:342
if (st.path == "/api/DispatchSortingCommand/InsertWaveInfo" && st.method == "POST")
{
    // ① 水位保护
    if (m_pQueue->size() >= MAX_TASK_QUEUE)  // MAX_TASK_QUEUE = 5
        → errResponse("服务器繁忙", "503")

    // ② 空 Body 校验
    if (st.body.isEmpty())
        → errResponse("Body为空", "400")

    // ③ 入队（不解析 JSON，< 1ms 返回）
    WaveTask task;
    task.rawBody  = st.body;
    task.recvTime = QDateTime::currentMSecsSinceEpoch();
    m_pQueue->push(task);                    // 非阻塞入队
    → okResponse("accepted")
}
```

### 2.2 异步解析（ParseWorker 后台线程）

```
  TaskQueue::pop() → 阻塞等待新任务
      │
      ▼
  QJsonDocument::fromJson(task.rawBody)
      │
      ├── 提取 orderCode / orderQty
      ├── 遍历 items[]
      │   ├── 取出 inco → gridNum 映射
      │   ├── 同品多格口: "1" + "2" → "1,2" (逗号合并)
      │   └── 构建 newMap[inco] = GridEntry{gridNum, gridType, gridCount}
      │
      ├── DoubleBuffer::prepareSwap(newMap)
      │   └── std::atomic::exchange() ← 原子交换，无锁写入
      │
      └── emit waveParsed(orderCode, skuCount, orderQty, elapsedMs, recvSet)
           │
           │ Qt::QueuedConnection
           ▼
      HttpServer lambda:
        m_pWaveMgr->setWaveData(orderCode, orderQty, skuCount)
        m_pWaveMgr->setRecvSet(recvSet)
        m_warnedPlcFailCodes.clear()
```

### 2.3 封装要点

| 维度 | 实现 |
|---|---|
| **网络层** | 不解析 JSON，仅 `memcpy` + 入队，< 1ms |
| **队列层** | `TaskQueue`: `QMutex + QWaitCondition`，水位保护 max=5 |
| **解析层** | `ParseWorker`: 独立 `QThread`，`LowPriority` |
| **读取层** | `DoubleBuffer`: `std::atomic<QMap*>` + `exchange()` |
| **业务层** | `WaveManager`: 状态 `IDLE → RECEIVED` |
| **线程安全** | 网络层→队列层: `commitNoWait` 异步隔离 |
| **双写日志** | `HTTP_INFO` (hlog 文件) + `emit logMessage` (UI 窗口) |

## 三、接口二：格口容器绑定

### 3.1 路由入口

```cpp
// HttpServer.cpp:434
if (st.path == "/api/DispatchSortingCommand/BindingLatticePort" && st.method == "POST")
{
    QJsonDocument d = QJsonDocument::fromJson(st.body);
    QJsonObject result = handleBindingLatticePort(d.object());
    sendJsonResponse(pSender, dwConnID, result);
}
```

### 3.2 业务处理

```cpp
QJsonObject HttpServer::handleBindingLatticePort(const QJsonObject& req)
{
    // ① 参数校验
    QString boxcode     = req["boxcode"].toString().trimmed();
    QString latticehole = req["latticehole"].toString().trimmed();
    if (boxcode.isEmpty() || latticehole.isEmpty())
        → errResponse("参数缺失", "400")

    // ② 写入绑定映射（线程安全）
    {
        std::lock_guard<std::mutex> lock(m_containerMutex);
        m_containerBindings[latticehole] = boxcode;
    }

    // ③ 双写日志
    HTTP_LOG_INFO("容器绑定成功 latticehole=%s → boxcode=%s total=%d", ...)
    emit logMessage("[容器绑定] 格口%1 → 容器%2 (共%3条)", ...)

    // ④ 特殊响应格式（文档要求 Int code）
    QJsonObject r;
    r["code"]    = 200;          // Int 类型
    r["Message"] = "收到信息";    // 首字母大写
    return r;
}
```

### 3.3 数据结构

```cpp
// HttpServer.h
QMap<QString, QString>  m_containerBindings;  // latticehole(格口号) → boxcode(容器号)
std::mutex              m_containerMutex;     // 保护并发写入
```

### 3.4 封装要点

| 维度 | 实现 |
|---|---|
| **存储引擎** | `QMap<格口号, 容器号>` — 内存存储，O(log n) 插入 |
| **并发安全** | `std::mutex m_containerMutex` 保护写入 |
| **响应格式** | 特殊格式 `{code:Int, Message:String}`，以 WMS 文档为准 |
| **生命周期** | 绑定数据随波次取消/完成自动清理 |
| **双写日志** | `HTTP_LOG_INFO` (文件) + `emit logMessage` (UI) |

## 四、接口三：退货任务取消

### 4.1 路由入口

```cpp
// HttpServer.cpp:444
if (st.path == "/api/DispatchSortingCommand/CancelWave" && st.method == "POST")
{
    QJsonDocument d = QJsonDocument::fromJson(st.body);
    QJsonObject result = handleCancelWave(d.object());
    sendJsonResponse(pSender, dwConnID, result);
}
```

### 4.2 业务处理（三级校验 + 清理）

```cpp
QJsonObject HttpServer::handleCancelWave(const QJsonObject& req)
{
    QString orderCode    = req["orderCode"].toString().trimmed();
    QString cancelReason = req["cancelReason"].toString().trimmed();

    // ═══ 第一级：参数校验 ═══
    if (orderCode.isEmpty())
        → errResponse("缺少orderCode", "400")

    // ═══ 第二级：波次匹配校验 ═══
    if (!m_pWaveMgr || m_pWaveMgr->orderCode() != orderCode)
        → errResponse("波次不存在或已完结", "404")

    // ═══ 第三级：状态合法性校验 ═══
    int status = m_pWaveMgr->status();
    if (status >= WAVE_SORTING)              // 已开始分拣 → 不允许取消
        → errResponse("波次已开始分拣，不允许取消", "400")

    // ═══ 执行取消 ═══
    m_pWaveMgr->clearWave();                 // 清理分拣状态集

    {
        std::lock_guard<std::mutex> lock(m_containerMutex);
        m_containerBindings.clear();         // 清理容器绑定
    }

    // 双写日志（含取消原因）
    emit logMessage("[取消波次] orderCode=%1 reason=%2", ...)
    return okResponse();                     // "200" OK
}
```

### 4.3 状态转换图

```
  可取消范围          禁止取消范围
  ═══════════════    ═══════════════════════

  IDLE    RECEIVED   SORTING    COMPLETING   CLEANED
   (0)      (1)       (2)         (3)          (4)
    │        │          │            │            │
    └── ✓ ──┘          └───── ✗ ────┴──── ✗ ────┘
```

### 4.4 清理的数据

| 数据 | 操作 |
|---|---|
| `m_setCodeRecv` | `clear()` |
| `m_setCodeSorted` | `clear()` |
| `m_setCodeException` | `clear()` |
| `m_setCodeProcessing` | `clear()` |
| `m_mapCodeRetry` | `clear()` |
| `m_waveStatus` | `CLEANED → IDLE` |
| `m_bReported` | `false` |
| `m_containerBindings` | `clear()` |

### 4.5 封装要点

| 维度 | 实现 |
|---|---|
| **校验链** | 参数校验 → 波次匹配 → 状态合法性（三级逐级拦截） |
| **状态保护** | 已开始分拣（`>= SORTING`）的波次不可取消 |
| **关联清理** | 取消波次时同步清理容器绑定 |
| **日志记录** | 记录取消原因（`cancelReason`），便于追溯 |
| **可恢复性** | `CLEANED → IDLE` 自动回位，可接收新波次 |

## 五、响应格式封装

### 5.1 WMS 接口统一格式

```cpp
// 成功响应
QJsonObject okResponse(const QString& msg = "") {
    r["code"]     = "200";                              // String 类型
    r["message"]  = msg;
    r["sentTime"] = currentDateTime().toString("yyyy-MM-dd HH:mm:ss.000");
}

// 错误响应
QJsonObject errResponse(const QString& msg, const QString& code = "500") {
    r["code"]     = code;                               // "400"/"404"/"500"/"503"
    r["message"]  = msg;
    r["sentTime"] = currentDateTime().toString("yyyy-MM-dd HH:mm:ss.000");
}
```

### 5.2 容器绑定特殊格式

```cpp
r["code"]    = 200;          // Int 类型（非 String）
r["Message"] = "收到信息";    // 首字母大写
```

### 5.3 HTTP 响应发送

```cpp
void sendJsonResponse(IHttpServer* pSender, CONNID dwConnID,
                       const QJsonObject& json, USHORT status)
{
    QByteArray d = QJsonDocument(json).toJson(QJsonDocument::Compact);
    THeader h[1];
    h[0].name  = "Content-Type";
    h[0].value = "application/json; charset=UTF-8";
    pSender->SendResponse(dwConnID, status, nullptr, h, 1,
                          (const BYTE*)d.constData(), d.length());
}
```

## 六、日志管理封装

### 6.1 双写模式

每个接口都使用双写日志，确保人（UI）和文件（持久化）都可追溯：

```cpp
// 文件日志（hlog 框架，写入 ./log/HTTP/http.log）
HTTP_LOG_INFO("容器绑定成功 latticehole=%s → boxcode=%s total=%d", ...)
HTTP_LOG_WARN("CancelWave 波次已开始分拣 不允许取消 orderCode=%s status=%d", ...)

// UI 日志（Qt 信号，写入 MainWindow 日志窗口）
emit logMessage(QString("[容器绑定] 格口%1 → 容器%2 (共%3条)"), true)
emit logMessage(QString("[取消波次] 波次已取消 orderCode=%1"), false)
```

### 6.2 日志级别策略

| 级别 | 使用场景 | 示例 |
|---|---|---|
| `HTTP_LOG_INFO` | 正常业务操作 | 入队成功、绑定成功、取消成功 |
| `HTTP_LOG_WARN` | 需要关注的异常 | 队列满、参数缺失、状态不合法 |
| `HTTP_LOG_ERROR` | 严重错误 | PLC 发送失败 |
| `emit logMessage(..., false)` | UI 正常信息（绿色） | 操作成功 |
| `emit logMessage(..., true)` | UI 警告信息（红色） | 拒绝原因 |

## 七、线程模型（三个接口共用）

```
  HP-Socket I/O 线程 (×16)
      │
      │ OnMessageComplete() 回调
      ├── 取出 ConnState（拷贝）
      ├── commitNoWait(lambda)                ← 入队即返回，不阻塞 I/O
      └── return HPR_OK

  ┌─────────────────────────────────────────┐
  │  BusinessPool 工作线程 (×64)             │
  │                                         │
  │  processRequest(pSender, dwConnID, st)  │
  │      │                                   │
  │      ├── 路由匹配 (if/else 字符串比较)    │
  │      │                                   │
  │      ├── InsertWaveInfo                  │
  │      │   └── TaskQueue::push()           │
  │      │       (QMutex + QWaitCondition)   │
  │      │                                   │
  │      ├── BindingLatticePort              │
  │      │   └── m_containerMutex.lock()     │
  │      │       写入 QMap                    │
  │      │                                   │
  │      └── CancelWave                      │
  │          ├── m_pWaveMgr->status()         │
  │          │   (std::atomic, 无锁读)        │
  │          ├── m_pWaveMgr->clearWave()      │
  │          │   (std::mutex 保护)            │
  │          └── m_containerMutex.lock()      │
  │              clear QMap                   │
  │                                           │
  └───────────────────┬───────────────────────┘
                      │
                      ▼
  sendJsonResponse() → HP-Socket::SendResponse() (线程安全)
```

### 并发安全策略

| 数据 | 保护机制 | 持锁时间 |
|---|---|---|
| `m_connStates` | `std::mutex m_connMutex` | < 1μs |
| `TaskQueue::m_queue` | `QMutex + QWaitCondition` | < 1μs (push) |
| `m_containerBindings` | `std::mutex m_containerMutex` | < 10μs (写入/清理) |
| `WaveManager::m_waveStatus` | `std::atomic<int>` | 无锁 |
| `WaveManager::分拣状态集` | `std::mutex m_lock` | < 100μs |

## 八、关键封装决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 波次推送不解析 JSON | `commitNoWait` 入队，异步解析 | 避免 WMS 超时，< 1ms 返回 |
| 容器绑定用内存 Map | `QMap<格口, 容器>` | 数据量小（≤120 格口/波次），无需数据库 |
| 取消接口三级校验 | 参数→波次→状态 | 逐级拦截，精确返回错误原因 |
| 取消后不传 WMS | 仅本地清理 | 文档未要求取消回传，保持简单 |
| 响应格式分离 | WMS 接口 `{code, message, sentTime}` / 容器 `{code:Int, Message}` | 以文档为准，不强制统一 |
| 双写日志 | hlog 文件 + UI signal | 运维可查文件，操作员可看 UI |
