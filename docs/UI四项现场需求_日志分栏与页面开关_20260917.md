## 二、逐项实现

### ① 日志页：日志区 / 效率统计面板 宽度

> ★ 2026-09-17 后续口径（**取代**最初的"各占一半"）：**效率统计面板宽度 = 「波次信息」面板宽度**
> —— 两块上下对齐成一列。原"各占一半"的实现已作废，见 §六.⑦。

- `m_logEffSplit`（横向分隔条）两侧 stretch 均为 1；**右栏宽度由同步函数按「波次信息」面板实际宽度设定**：
  ```cpp
  void MainWindow::syncLogEffPanelWidth();   // 右栏 = m_grpWaveInfo->width()，左栏吃余量
  ```
- 调用点：① 效率面板首次创建后；② 面板由隐藏变显示时；③ **1 秒刷新定时器**（记住上次对齐宽度，
  未变化直接返回 → 零布局开销；用户手动拖动分隔条后不会被秒级覆盖，只有窗口/波次面板宽度变化才重新对齐）。
- 面板 `setMinimumWidth(280)` 保留（现场宽度远大于它，不会成为约束）。
- 面板显隐仍由「任务接收控制」区的**「效率统计」按钮**控制（按下=显示，默认开启）；
  按钮弹起时面板隐藏、日志区吃满整行宽度（行为不变）。

### ② 实时面板页：XML 开关（默认隐藏，重启生效）

```xml
<!-- ★ 实时面板页是否显示（false=隐藏该页，默认 false）。★★ 仅启动时读取一次：改这里要重启程序才生效 ★★ -->
<showLivePage>false</showLivePage>
```

- `AppConfig::showLivePage`（`define.h` 默认宏 `UI_SHOW_LIVE_PAGE_DEFAULT = false`）；
- `setupUI()` 里读**一次**：
  - `true` → 与改造前完全一致（创建「落格反馈数据（实时）」表 + 加入标签页）；
  - `false` → **不创建该表**（`m_tblLive = nullptr`）且不加页签。
- **为什么"连表都不创建"而不是 `setVisible(false)`**：实时面板有两条高频写入路径
  （RFID 推送、PLC 100ms 落格反馈批量），它们的**第一道守卫都是 `if (!m_tblLive) return;`** ——
  不建表即等于"隐藏期间零 UI 开销"（不插行、不裁行、不打标、不重绘），
  对日万级件的分拣主线程是净收益。
- `true/false` 都打一条启动日志：`启动：按配置隐藏「实时面板」页（showLivePage=false；改 XML 需重启生效）`。

### ③ 计划分配表页：XML 开关（默认隐藏，重启生效）

```xml
<!-- ★ 计划分配表页是否显示（false=隐藏该页，默认 false）。★★ 仅启动时读取一次：改这里要重启程序才生效 ★★ -->
<showPlanAllocPage>false</showPlanAllocPage>
```

- `AppConfig::showPlanAllocPage`（默认宏 `UI_SHOW_PLAN_ALLOC_PAGE_DEFAULT = false`）；
- `false` → 不加页签。该页的周期刷新 `refreshPlanAllocPage(false)` 自带判定
  「**本页不在前台 → 直接返回**」；页面不在标签页里 → 该判定恒成立 → **不取快照、不碰表格，空闲开销为 0**；
- 页面控件仍会构造（一个空表 + 几个标签，成本可忽略），因此**恢复显示不需要改任何代码**，只要把开关改 `true` 并重启。

### ④ 格口绑定面板：明文提示「异常口：66格口」

- 新增 `m_lblExceptionGrid`，位置在「刷新绑定状态 / 清空格口绑定 / 图例」之后、计数之前，
  字样 `异常口：66格口`（**客户指定表述**）；
- 格号来源 = `<exceptionGrid>`（现场 `66`），经 `parseWmsGridCodeToInt()` 归一，
  因此 `<exceptionGrid>066</exceptionGrid>` 或 `22066` 都显示为 **66**；
- 未配置（空 / `0`）→ `异常口：未配置`（此时面板**不隐藏任何格口**，66 格全显示）；
- tooltip 里写清"为什么看不到它"：
  > 配置的物理异常口 = 66 号格口（`<exceptionGrid>66</exceptionGrid>`）。
  > 该口**不在本面板展示**：不显示格子、不计入「已绑定/已锁格/未绑定」计数。
  > 它的用途：承接超计划件，需人工清出；该口的落格件不上传 WMS（不进 H7）。
- 原图例 tooltip 的"配置的物理异常口（默认 66）不在此面板展示"一并改写为与上面一致的口径，避免两处表述不一致。

## 三、验收步骤

1. **部署**：重新编译 Release（产物直接落 `release_WcsHttpServer\WCS_httpServer.exe`），
   确认 exe 时间戳晚于源文件；**关闭并重启程序**（②③ 是启动时读取）。
2. **①**：切到「运行日志」页 → 左侧日志区与右侧「RFID 推送效率统计（当日观察）」面板**宽度目测各占一半**
   （拖动窗口后仍按同比例伸缩）；拖动中间分隔条可改比例；再点「效率统计」→ 面板隐藏、日志吃满宽度，
   再点 → 恢复约一半宽并立即出数。也可用 `python test/ui_layout_probe.py` 截图留档。
3. **②**：`config/http_server.xml` 里 `<showLivePage>false</showLivePage>` → 重启 → 左侧标签页**没有「实时面板」**，
   运行日志出现 `启动：按配置隐藏「实时面板」页…`；改成 `true` 重启 → 该页恢复且行为与改造前一致
   （RFID 先占一行、PLC 反馈就地补全、超上限裁旧行）。
4. **③**：`<showPlanAllocPage>false</showPlanAllocPage>` → 重启 → 标签页**没有「计划分配表」**；
   改成 `true` 重启 → 该页恢复（切到该页立即取一次快照、每 2 秒节流刷新）。
5. **④**：切到「容器绑定状态」页 → 按钮行右侧显示 `异常口：66格口`；
   鼠标悬停出现"不在本面板展示/不计数/只收超计划件"的解释；
   把 `<exceptionGrid>` 改成空并重启 → 显示 `异常口：未配置`，且 66 格全部显示（不再隐藏）。
6. **不立刻生效自检**：程序运行中把 `<showLivePage>` 改成 `true` → **本次运行不变**（页面不出现），
   重启后才出现；且配置文件不会被程序自动保存覆盖（`ConfigManager::save` 保存前比对外部改动并先重载）。
7. **回归**：`tests\run_tests.bat` 全绿；核心分拣链路（RFID→PLC→落格→H7/H8）与波次切回逻辑不受影响。

## 四、已知边界与取舍

- **②③ 的开关是"启动期开关"**：改 XML 不即时生效（这正是现场要求）。运行中改也不会丢：
  下次启动生效；配置自动保存有"外部改动检测 + 先重载再写"保护，不会把手改内容覆盖掉。
- **实时面板隐藏后不积累历史行**：再次打开（改 true + 重启）后，面板从"该次启动之后"的推送开始显示
  （不会补历史）——因为它本来就没有落库，只有内存行。
- **① 只影响「运行日志」页**：波次信息面板、设备状态等其它区域的宽度分配不变。
- **④ 只改文字提示**：异常口在后台行为完全不变（仍可被 H6 绑定、仍承接超计划件、其落格件仍不进 H7）。
- 两页隐藏**不影响任何业务功能**：计划分配（选格/封顶/改投异常口）在后台照常运行，
  只是没有那个可视化页面；实时面板同样是纯展示。

## 七、同日追加两项（效率面板宽度对齐 / 开始接收任务清空波次面板）

| # | 需求 | 实现口径 |
| --- | --- | --- |
| ⑨ | **效率统计面板宽度 = 「波次信息」面板宽度** | 新增 `MainWindow::syncLogEffPanelWidth()`：把「运行日志」页分隔条右栏宽度设为 `m_grpWaveInfo->width()`；由 1 秒定时器 + 面板显示时调用，宽度未变直接返回（见 §二① 的口径替换说明） |
| ⑩ | **点「开始接收任务」也清空「波次信息」面板数据** | 新增 `HttpServer::resetWavePanelToIdle(reason)`：与「新任务」同口径把当前波次**切出**（内存清空 → 面板复位为"等待 WMS 下发"；进度/明细/计划/落格/异常保留于 DB，可切回）；调用点 = `HttpServer::startReceive()`（紧跟 `restoreWaveFromDB()` 之后） |

### ⑨ 效率统计面板宽度对齐

- 「波次信息」面板在第一行右侧（占整行一半，可拖动分隔条改变宽度）；
  效率统计面板在「运行日志」页右侧 → 两者同宽后上下对齐成一列；
- 对齐逻辑**记得上次应用的宽度**，宽度未变时不碰布局（避免每秒 setSizes 产生抖动）；
- 现场手动拖动日志分隔条 → 保持到下一次"窗口尺寸变化 / 波次面板宽度变化"才重新对齐（权衡：以对齐优先）。

### ⑩ 点「开始接收任务」清空波次信息面板

**现场问题**：停止接收 → 再次点「开始接收任务」后，波次信息面板仍显示上一波次的
波次号/状态/计划件数/已分拣/异常/H7/H8/更新时间等**旧数据**，看起来像"任务还在跑"。

**口径（与「新任务」完全一致）**：`startReceive()` 里在 `restoreWaveFromDB()` 之后调用
`resetWavePanelToIdle("开始接收任务")`：

| 项 | 行为 |
| --- | --- |
| 波次信息面板 | 复位为"等待 WMS 下发新波次"（内存波次切出 → 面板清空，发 `waveResumed` 刷新 UI） |
| 进度/明细/计划/落格/异常 | **保留于 DB**（状态保持原值）→ 可从「波次数据历史记录」切回继续 |
| 未成功 H7/H8 | 保留在 outbox；切回该波次时自动补发 |
| 格口绑定 | 已由同一链路上的 `restoreWaveFromDB()` 清空（内存清空 + DB 归档留痕）→ 面板全「未绑定」 |
| 无进行中波次时 | 只写一条 INFO（面板本就是初始状态），不做任何动作 |
| 待执行队列 | 原样保留（不自动执行；与「新任务」一致） |

- 启动时自动执行的那次「开始接收任务」也会走本逻辑（此时内存无波次 → 直接返回，无副作用）；
- 与既有"启动=新任务状态"口径一致：**不自动装载任何波次**，等 WMS 重新下发；
- 该改动属**内存/UI 层**（与既有「切出」同一条链路 `switchAwayCurrentWave`），
  DB 层契约未变，故自测仍为既有 7 用例（258 项断言）全绿。
