## 二、功能一：格口分配（H4）

### 2.1 接口规格

```
POST http://172.30.10.101:8191/api/DispatchSortingCommand/InsertWaveInfo
Content-Type: application/json

请求体:
{
    "orderCode": "PB202203200003",       // 波次号
    "orderQty": "12312",                 // 波次件数
    "items": [
        {
            "obxCode": "...",            // ★ 不需要（客户标注）
            "inco": "WV34S1CN2001B60L",  // 商品编码（核心键）
            "epcn": "...",               // ★ 不需要（客户标注）
            "gridNum": "1",              // 格口号（可多个逗号分隔）
            "gridNumber": "100",         // 该格口对应件数
            "gridType": "普通格口",       // 格口属性
            "volu": "1234"               // ★ 不需要（客户标注）
        }
    ]
}

响应:
{
    "resultCode": "0",
    "success": true,
    "resultData": "推送WCS数据成功!波次号：PK2025042900002",
    "resultTime": "2025-04-30 09:28:55.6412"
}
```

### 2.2 业务规则

| 规则 | 说明 | WCS_httpServer 实现 |
|------|------|---------------------|
| **多对多格口** | 同一商品可对应多个格口，一个格口可对应多个商品 | ✅ comma-separated merge in ParseWorker |
| **分级分拣** | 分到SKU/款/库区/通道，擦款混分 | ⚠️ 依赖 WMS 侧业务逻辑，本程序只存储映射 |
| **二次投线** | 设备读码异常可二次投线 | ✅ retryCount ≤ maxRetryCount in WaveManager |
| **同品冲突** | 库存分类和发货同时出现同品时特殊处理 | ⚠️ 依赖外部程序实现，本程序提供 API 查询 |
| **专属格口锁库** | 指定库区订单锁库专属格口 | ⚠️ 依赖 WMS 侧分配，本程序只存储 |
| **obxCode/epcn/volu** | 实际不需要 | ✅ ParseWorker 不依赖这些字段 |

### 2.3 格口分配全流程

```
WMS POST InsertWaveInfo
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│ HttpServer::OnRequest()                                     │
│   path == "/api/.../InsertWaveInfo"                        │
│   ① memcpy Body → QByteArray                               │
│   ② 封装 WaveTask {rawBody, recvTime}                      │
│   ③ TaskQueue::push(task)  ← 非阻塞入队                    │
│   ④ 返回 200 {"resultCode":"0","success":true}             │
│   ⏱️ < 1ms                                                  │
└──────────────────────┬──────────────────────────────────────┘
                       │ 入队
┌──────────────────────▼──────────────────────────────────────┐
│ ParseWorker::run() (低优先级线程)                            │
│   ① task = TaskQueue::pop()  ← 阻塞等待                     │
│   ② QJsonDocument::fromJson(rawBody)                       │
│   ③ 遍历 items[i]:                                         │
│       key = items[i].inco                                  │
│       val = GridEntry{gridNum, gridType, gridNumber}       │
│       同品多格口: 逗号合并去重 "1"+"2" → "1,2"             │
│   ④ 构建 new QMap<inco, GridEntry>                         │
│   ⑤ DoubleBuffer::prepareSwap(newMap)  ← 原子指针交换       │
│   ⑥ 记录日志: SKU数, 耗时                                   │
└──────────────────────┬──────────────────────────────────────┘
                       │ 原子交换
┌──────────────────────▼──────────────────────────────────────┐
│ DoubleBuffer<QString, GridEntry>                            │
│   std::atomic<QMap*> m_pActive                             │
│   查询 API: GET /api/query?code=xxx                         │
│   → 无锁读取，返回 {"grid":"1", "gridType":"普通格口"}     │
└─────────────────────────────────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────────┐
│ WaveManager::setWaveData(orderCode, orderQty, skuCount)     │
│   状态: IDLE → RECEIVED                                     │
│   跟踪: m_setCodeRecv = {推送的所有inco集合}                │
└─────────────────────────────────────────────────────────────┘
```

## 三、功能二：落格回传（H8）

### 3.1 接口规格

```
WCS → WMS 回传

测试环境:
  URL:  http://182.92.166.232/gids5/service/thirdPartyData/dz_bxh_wcs_cs
  AppKey: dz_bxh_wcs_cs

正式环境:
  URL:  http://47.93.21.77:9090/gids5/service/thirdPartyData/dz_bxh_wcs_zs
  AppKey: dz_bxh_wcs_zs

method: gwisSubProductClassifyEndOrder

请求:
{
    "head": {
        "orderCode": "PB202203200003",
        "orderType": "02",                          // 固定值
        "sumLocation": "120",                       // 分类总库位数
        "operuserDate": "2024-01-01 13:00:00",
        "operuserCode": "admin",
        "operuserName": "管理员"
    }
}

响应:
{
    "success": true,
    "body": "产品分类任务完结--同步成功!",
    "ts": "2024-01-01 13:00:00:000"
}
```

### 3.2 业务规则

| 规则 | 说明 |
|------|------|
| **波次级回传** | 整个波次完成才回传，不是逐件回传 |
| **orderType 固定** | 恒为 `"02"` |
| **sumLocation** | 分类总库位数 = 该波次涉及的**去重格口数** |
| **回传时机** | 所有 SKU 分拣完成 或 超时 |

### 3.3 波次完结判定

```
isWaveComplete() 判定逻辑:
═══════════════════════════════════════════

条件①: 全部SKU已分拣
  m_setCodeSorted.size() + m_setCodeException.size() >= m_setCodeRecv.size()
  即: 已分拣 + 异常 ≥ 推送总数
  → 返回 true

条件②: 超时强制完结
  waveTimeoutMin > 0
  && (当前时间 - m_waveStartTime).seconds() > waveTimeoutMin * 60
  → 返回 true

条件③: 手动触发
  管理员点击 UI "手动回传" 按钮
  → 强制执行回传

以上任一条件满足 → 触发回传
```

### 3.4 回传全流程

```
                 波次完结判定通过
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│ WaveManager 状态: SORTING → COMPLETING                      │
│ 防止重复回传: m_waveStatus == COMPLETING → 跳过              │
└──────────────────────┬──────────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────────┐
│ HttpClient::sendWaveComplete(orderCode, sumLocation)         │
│                                                              │
│ ① 构造 JSON:                                                │
│    head.orderCode     = orderCode                           │
│    head.orderType     = "02"                                │
│    head.sumLocation   = DoubleBuffer.uniqueValueCount()     │
│    head.operuserDate  = QDateTime::current()                │
│                                                              │
│ ② CHttpClient 异步 POST → WMS 回传 URL                      │
│    SetTimeout(2000ms)                                       │
│    SetAppkey(appkey)                                        │
│                                                              │
│ ③ 回调:                                                     │
│    OnResponse(200):                                         │
│      JSON["success"] == true → COMPLETING → CLEANED         │
│      JSON["success"] == false → 恢复 SORTING，等待重试      │
│                                                              │
│    OnError(超时/网络):                                       │
│      → 恢复 SORTING 状态                                    │
│      → 下次落格信号时重新触发 isWaveComplete()               │
└─────────────────────────────────────────────────────────────┘
```

### 3.5 WCS_httpServer 能力评估

| 子功能 | 状态 | 说明 |
|--------|------|------|
| 波次完结判定 | ✅ 已实现 | WaveManager::isWaveComplete() 三个条件 |
| 异步回传 | ✅ 已实现 | HttpClient 异步回调 |
| sumLocation 计算 | ✅ 已实现 | DoubleBuffer::uniqueValueCount() |
| 2秒超时 | ✅ 已实现 | HttpClient::setTimeout(2000) |
| 失败重试 | ✅ 已实现 | OnError → 恢复SORTING状态 |
| 重复回传保护 | ✅ 已实现 | WAVE_COMPLETING 状态检查 |
| 手动回传 | ✅ 已实现 | MainWindow "手动回传" 按钮 |
| 满箱切换 H7 | ⚠️ 需新增 | 见下方 5.3 节 |
| **结论** | **✅ 核心功能满足** | H7 满箱切换需补充 |

## 四、功能三：任务取消（H5）

### 4.1 接口规格（需新增）

```
POST http://{host}:8191/api/cancelWave
Content-Type: application/json

请求:
{
    "orderCode": "PB202203200003",
    "reason": "单据需增加明细"
}

响应成功:
{
    "success": true,
    "resultCode": "0",
    "errorMsg": null,
    "resultData": "波次 PB202203200003 已取消"
}

响应失败（已开始分拣）:
{
    "success": false,
    "resultCode": "-1",
    "errorMsg": "波次已开始分拣，不允许取消",
    "resultData": null
}
```

### 4.2 业务规则（来自客户 H5）

```
        取消规则决策树
 ════════════════════════════════

  WMS 下发取消指令
       │
       ▼
  检查 m_waveStatus
       │
  ┌────┴────┐
  │         │
  IDLE/     SORTING/
  RECEIVED  COMPLETING/...
  │         │
  ▼         ▼
 允许取消   拒绝取消
  │         │
  │         返回:
  │         errorMsg:
  │         "波次已开始分拣，
  │          不允许取消"
  │
  ▼
  ① 清理 DoubleBuffer 格口映射
  ② 清理 WaveManager 分拣状态
  ③ 状态: → WAVE_CANCELLED
  ④ 记录日志
  ⑤ 返回成功
```

### 4.3 取消范围

| 场景 | 允许 | 说明 |
|------|------|------|
| 波次已接收但未开始分拣 (IDLE/RECEIVED) | ✅ | 可安全取消 |
| 波次分拣中 (SORTING) | ✗ | 不可取消（已有包裹在途） |
| 波次回传中 (COMPLETING) | ✗ | 不可取消（回传进行中） |
| 波次已完成 (CLEANED) | ✗ | 已结束无需取消 |
| 单条 SKU 取消 | ⚠️ 暂不支持 | 客户方案未提及单品取消 |

### 4.4 取消处理中的关键操作

```
执行取消时需要清理的数据:

┌──────────────────────────────────────────────────────────────┐
│ 1. DoubleBuffer                                              │
│    → 将格口映射替换为空 Map (prepareSwap(new empty QMap))    │
│                                                              │
│ 2. WaveManager                                               │
│    → m_setCodeRecv.clear()                                   │
│    → m_setCodeSorted.clear()                                 │
│    → m_setCodeException.clear()                              │
│    → m_setCodeProcessing.clear()                             │
│    → m_mapCodeRetry.clear()                                  │
│    → m_waveStatus = WAVE_CANCELLED                           │
│    → m_orderCode = ""                                        │
│                                                              │
│ 3. TaskQueue                                                 │
│    → clear() 清空积压任务队列                                │
│    （如果有待解析的同一波次任务）                             │
│                                                              │
│ 4. 日志                                                      │
│    → WCS_INFO("[Cancel] 波次 %s 已取消", orderCode)          │
│    → 记录取消原因和操作时间                                   │
└──────────────────────────────────────────────────────────────┘
```

### 4.5 波次状态机扩展

```
现有状态机:
  IDLE → RECEIVED → SORTING → COMPLETING → CLEANED → IDLE

扩展后:
  IDLE → RECEIVED → SORTING → COMPLETING → CLEANED → IDLE
           │                                    ↑
           └──→ WAVE_CANCELLED ─────────────────┘
```

### 7.3 H5 任务取消 — 伪代码

```cpp
// HttpServer::OnRequest 新增路由
if (strcmp(path, "/api/cancelWave") == 0)
{
    QJsonObject req = QJsonDocument::fromJson(body).object();
    QString orderCode = req["orderCode"].toString();

    if (m_pWaveMgr->status() >= WAVE_SORTING)
    {
        // 已开始分拣，拒绝取消
        respJson["success"] = false;
        respJson["errorMsg"] = "波次已开始分拣，不允许取消";
    }
    else
    {
        // 允许取消
        m_pWaveMgr->cancelWave(orderCode, req["reason"].toString());

        // 替换格口映射为空
        auto* emptyMap = new QMap<QString, GridEntry>();
        m_pBuffer->prepareSwap(emptyMap);

        // 清空任务队列
        m_pQueue->clear();

        respJson["success"] = true;
        respJson["resultData"] = QString("波次 %1 已取消").arg(orderCode);
    }
}

// WaveManager 新增方法
void WaveManager::cancelWave(const QString& orderCode, const QString& reason)
{
    std::unique_lock<std::mutex> lock(m_lock);
    clearWave();  // 复用已有清理方法
    m_waveStatus = WAVE_CANCELLED;

    WCS_INFO("[Cancel] 波次 %s 已取消 原因:%s",
        orderCode.toLocal8Bit().data(),
        reason.toLocal8Bit().data());
}
```

## 八、最终结论

### 8.1 WCS_httpServer 能否实现三个功能

| 功能 | 能否实现 | 工作量 | 风险 |
|------|----------|--------|------|
| **H4 格口分配** | ✅ 已实现 | 0 | 无 |
| **H8 落格回传** | ✅ 已实现 | 0 | 无 |
| **H5 任务取消** | ✅ 可实现 | ~80行代码 | 低（逻辑简单） |
| **H7 满箱切换** | ✅ 可实现 | ~120行代码 | 低（后续迭代） |

### 8.2 实施优先级

```
P0 (必须，当前已完成):
  H4 格口分配 → 接收插入波次
  H8 落格回传 → 波次完结回传

P1 (必须，需新增):
  H5 任务取消 → 未分拣时允许取消

P2 (后续迭代):
  H7 满箱切换 → 满箱通知WMS
```

### 8.3 与同行方案对比

| 维度 | 同行参考方案 | WCS_httpServer 方案 | 优势 |
|------|-------------|---------------------|------|
| 格口查询 | 内存 Map + mutex | DoubleBuffer 无锁 | 零延迟 |
| 解析方式 | QTcpServer 同步 | HP-Socket + ParseWorker 异步 | 不阻塞网络 |
| 回传模式 | 波次级 | 波次级 | 一致 |
| 取消保护 | markCodeSorted 提前调用 | 状态机 WAVE_SORTING 检查 | 更安全 |
| 独立性 | 嵌入 WCSApp | 独立进程 | 崩溃隔离+热升级 |
