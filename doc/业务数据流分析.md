# WCS_httpServer 业务数据流分析

> 以数据为核心视角，展示业务数据如何在多线程/多通道之间流转，代码版本 v6.0

## 一、数据流全景图

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                         业务数据流全景（双向）                                    │
│                                                                                 │
│   正向流：WMS ──► WCS_httpServer ──► PLC（S7 DBWrite + TCP 文本双通道）           │
│   反向流：WMS ◄── WCS_httpServer ◄── PLC（TCP 文本反馈）                          │
│                                                                                 │
│  ┌─────────┐   HTTP POST   ┌──────────────────┐   S7 DBWrite (DB1.1000, 42字节)  │
│  │   WMS   │──────────────►│  WCS_httpServer  │────────────── S7 ──────────► PLC│
│  │ 仓库系统 │◄──────────────│  (多线程/多通道)   │── TCP文本 {条码|格口|小车号} ──►│
│  └─────────┘  波次完结通知  └──────────────────┘◄──── TCP落格反馈 ──────────────│
│                                          │            {start}/{stop}           │
│                                          │  S7 DB77 锁格轮询 (1s, 200位)        │
│                                          └──────────────────────────────────►  │
│                                                                                 │

│    WCS→WMS: HTTP POST JSON {head:{orderCode, sumLocation, ...}}               │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 三、正向数据流：WMS → WCS → PLC

### 3.1 InsertWaveInfo（退货格口分配）— 数据入队与解析

**接口路径**: `POST /api/DispatchSortingCommand/InsertWaveInfo`

**数据路径**: WMS HTTP 报文 → 网络层 → 任务队列 → 解析线程 → 双缓冲 → 主线程状态机

```
WMS POST /api/DispatchSortingCommand/InsertWaveInfo
Body: ~250KB JSON (5000 items)
       │
       ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ① HP-Socket I/O 工作线程 (×16)                                         │
│                                                                         │
│  OnMessageComplete()                                                    │
│    ├── ConnState 拷贝 {method, path, queryString, body}                │
│    ├── commitNoWait(lambda)  → 入业务线程池队列                          │
│    └── return HPR_OK  (< 1ms, 不阻塞网络 I/O)                           │
└──────────────────┬─────────────────────────────────────────────────────┘
                   │  数据传递：ConnState 栈拷贝
                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ② BusinessPool 工作线程 (×90, 取一空闲)                                 │
│                                                                         │
│  processRequest()                                                       │
│    ├── 路由匹配：API_INSERT_WAVE_INFO (define.h#L100)                    │
│    ├── 队列满检查：m_pQueue->size() >= 5? → 503 拒绝                     │
│    ├── WaveTask{rawBody, recvTime} 入队                                 │
│    └── sendJsonResponse({code:"200", message:"accepted", ...})          │
│        总耗时 < 1ms                                                     │
└──────────────────┬─────────────────────────────────────────────────────┘
                   │  数据传递：WaveTask {rawBody}
                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ③ ParseWorker 线程 (×1, LowPriority)                                   │
│                                                                         │
│  run() 循环:  [ParseWorker::run](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/ParseWorker.cpp#L20-L105)                                           │
│    TaskQueue::pop() 阻塞等待  [TaskQueue](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/TaskQueue.h#L24-L82)                                   │
│      │                                                                  │
│      ├── QJsonDocument::fromJson(task.rawBody)  (3~5s, 5000 SKU)       │
│      ├── 遍历 items[] → 构建 QMap<inco, GridEntry>                      │
│      │   GridEntry {  [DoubleBuffer.h](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/DoubleBuffer.h#L25-L36)                                                  │
│      │     gridNum, gridType, gridCount,  // 格口信息                   │
│      │     orderCode, orderQty, skuCount   // 批次信息                  │
│      │   }                                                              │
│      ├── DoubleBuffer::prepareSwap(newMap)  // 原子指针交换              │
│      └── emit waveParsed(orderCode, skuCount, orderQty, elapsedMs, recvSet) │
│           Qt::QueuedConnection → 跨线程到主线程                          │
└──────────────────┬─────────────────────────────────────────────────────┘
                   │  数据传递：信号槽 + QueuedConnection
                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ④ Qt Main 线程                                                         │
│                                                                         │
│  HttpServer 构造函数中 lambda 连接 (HttpServer.cpp#L53-L62):            │
│    ├── WaveManager::setWaveData(orderCode, orderQty, skuCount)          │
│    │   ├── m_orderCode / m_orderQty 设置                                │
│    │   ├── m_waveStartTime = 当前时间                                   │
│    │   └── 状态机: IDLE → RECEIVED                                     │
│    ├── WaveManager::setRecvSet(recvSet)  // 全部 inco 集合               │
│    └── 重置 PLC 发送失败警告集合: m_warnedPlcFailCodes.clear()           │
└────────────────────────────────────────────────────────────────────────┘
```

**关键设计**：

- 网络层不碰 JSON → 永不阻塞 I/O 线程
- 入队后立即返回 HTTP 200 → WMS 不会超时
- ParseWorker 低优先级 → 不抢占 PLC/扫描实时性
- DoubleBuffer 原子交换 → 读线程（分拣查询）零阻塞

**响应格式**:

```json
{
  "code":"200",
  "message":"accepted",
  "sentTime":"2026-07-27 10:00:00.000"
}
```

## 四、PLC 通信数据流（双通道发送 + 单通道反馈）

### 4.1 PlcManager::sendCodeInfo — 双通道数据发送

**数据路径**: 业务线程 → S7 DBWrite + TCP 文本双通道 → PLC

```
BusinessPool / Qt Main 调用
       │
       ▼
┌────────────────────────────────────────────────────────────────────────┐
│  PlcManager::sendCodeInfo (PlcManager.cpp#L121-L221)                   │
│                                                                         │
│  ┌─ 通道1: S7 DBWrite (Snap7) ──────────────────────────────────────┐ │
│  │                                                                     │ │
│  │  if (m_S7Plc && m_S7Plc->isConnected())                             │ │
│  │  {                                                                 │ │
│  │      QByteArray sSend = barcode.toLatin1();                        │ │
│  │      m_S7Plc->writeCodeInfo(sSend, vecGrid);                       │ │
│  │      // 写入 DB1 Offset 1000, 42 字节                              │ │
│  │      // 与 WCSApp 完全一致                                          │ │
│  │  }                                                                 │ │
│  │  m_s7SendCount++ / m_s7SendErrCount++                              │ │
│  └─────────────────────────────────────────────────────────────────────┘ │
│                                                                         │
│  ┌─ 通道2: TCP 文本协议 ──────────────────────────────────────────────┐ │
│  │                                                                     │ │
│  │  lock(m_clientMutex)                                                │ │

**数据转换细节**:

| 数据源          | 数据形态                        | 转换操作                               | 目标形态                          |
| ------------ | --------------------------- | ---------------------------------- | ----------------------------- |
| DoubleBuffer | GridEntry.gridNum = "15"    | 3位补零                               | "015"                         |
| DoubleBuffer | GridEntry.gridNum = "1,2,3" | split(',')                         | vector{1, 2, 3}               |
| 固定值          | car = 1                     | 3位补零                               | "001"                         |
| TCP 拼接       | barcode + grid + car        | `QString("{%1\|%2\|%3}").arg(...)` | "{ST1234567890123\|015\|001}" |
| S7 写入        | barcode + vecGrid           | m_S7Plc->writeCodeInfo             | DB1.1000, 42字节                |

**补充：原始指令发送** — [PlcManager::sendRawCommand](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/PlcManager.cpp#L223-L245) 支持直接发送原始 TCP 文本指令（如 `{start}`、`{stop}`），不经过 S7 通道，仅遍历 TCP 客户端群发。用于手动控制 PLC 批次起停。

**补充：发送状态信号** — `sendCodeInfo` 在返回前会 emit [`plcSendInfo(barcode, grids, overallSuccess)`](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/PlcManager.cpp#L207)，供 UI 实时显示每条码的发送结果（成功/失败、格口号）。

### 4.2 PLC 落格反馈 → 分拣标记 → 波次完结回传（反向数据流）

**数据路径**: PLC 传感器 → TCP 报文 → PlcManager 解析 → 双通道信号 → WaveManager 标记 → 完结判定 → HTTP 回传 WMS

```
PLC 落格传感器触发
       │
       │ TCP {WV34001|122|1}  端口 8192
       ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ① PlcManager TCP 回调 (HP-Socket I/O 线程)                             │
│                                                                         │
│  OnReceive(pData, iLength)  (PlcManager.cpp#L518-L530)                  │
│    ├── m_recvCount.fetch_add(1)                                        │
│    ├── QByteArray rawData((const char*)pData, iLength)                  │
│    └── parsePlcFeedback(rawData)  // 解析 + 信号发射全程在 I/O 线程      │
└──────────────────┬─────────────────────────────────────────────────────┘
                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ② parsePlcFeedback (PlcManager.cpp#L574-L646)                          │
│                                                                         │
│  QString qdata = QString::fromLocal8Bit(rawData);                       │
│  QRegularExpression re("\\{(.*?)\\}");                                  │
│  QRegularExpressionMatchIterator it = re.globalMatch(qdata);            │
│                                                                         │
│  while (it.hasNext())                                                   │
│  {                                                                      │
│      QString content = it.next().captured(1).trimmed();                 │
│                                                                         │
│      if (content == "start")  → emit plcBatchStart()    // 批次开始     │
│      if (content == "stop")   → emit plcBatchStop()     // 批次停止     │
│                                                                         │
│      QStringList parts = content.split('|');                            │
│      code = parts[0]; grid = parts[1]; car = parts[2] (或 "1")         │
│                                                                         │
│      ├── 更新 m_lastRecvCode / m_lastRecvGrid / m_lastRecvCar           │
│      ├── LIFE_STAGE_PLC_FEEDBACK(code, grid)  // 生命周期日志           │
│      │                                                                 │
│      ├── emit plcFeedbackReceived(code, grid, car)  // 业务信号         │
│      │   Qt::QueuedConnection → Qt Main 线程 (用于 markSorted)          │
│      │                                                                 │
│      └── m_feedbackBatchBuffer.append(entry)  // 批量缓冲区             │
│          (上限 FEEDBACK_BATCH_MAX_SIZE=200)                            │
│  }                                                                      │
└──────────────────┬─────────────────────────────────────────────────────┘
                   │
                   ├── 信号 A: plcFeedbackReceived (逐条, 业务标记)
                   │   Qt::QueuedConnection
                   │
                   ├── 信号 B: plcFeedbackBatch (批量, UI 刷新, 每 100ms)
                   │   QTimer::flushFeedbackBatch 定时触发
                   │
                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ③ 双通道信号处理 (Qt Main 线程)                                         │
│                                                                         │
│  通道 A — plcFeedbackReceived (适用于业务逻辑, 逐条):                    │
│  ┌────────────────────────────────────────────────────────────────────┐ │
│  │ HttpServer 构造函数中连接 (HttpServer.cpp#L68-L76):                  │ │
│  │  connect(m_pPlcMgr, &PlcManager::plcFeedbackReceived,              │ │
│  │      this, [this](const QString& code, const QString& grid,        │ │
│  │                    const QString& car) {                           │ │
│  │          Q_UNUSED(grid); Q_UNUSED(car);                            │ │
│  │          if (!m_pWaveMgr) return;                                  │ │
│  │          m_pWaveMgr->markSorted(code);  // 标记已分拣               │ │
│  │          HTTP_LOG_INFO("PLC反馈自动分拣 code=%s", ...);             │ │
│  │          emit logMessage(...);                                     │ │
│  │      }, Qt::QueuedConnection);                                     │ │

## 八、关键设计决策与数据一致性保障

### 8.1 为什么使用 DoubleBuffer 而非 mutex 保护 Map？

| 方案                    | 读性能           | 写性能              | 实现复杂度 | 适用场景       |
| --------------------- | ------------- | ---------------- | ----- | ---------- |
| `std::mutex + QMap`   | 加锁 ~1μs       | 加锁 ~1μs          | 低     | 读写均衡       |
| `QReadWriteLock`      | 读无竞争 ~100ns   | 写加锁 ~1μs         | 中     | 读多写少       |
| `DoubleBuffer (原子指针)` | 原子 load ~50ns | 构建新 Map + 交换 ~3s | 中     | **读极多写极少** |

**本系统选择 DoubleBuffer 的原因**：

- 批量发送时 5000 次连续读取，无锁避免 5000 次 mutex 开销
- 运行时查询高频读取条码→格口映射，要求 < 1μs 响应
- 写入频率极低：只有新波次推送时才写入一次（分钟级）

### 8.2 为什么使用双通道（S7 + TCP）发送？

**当前代码实现**（[PlcManager.cpp:122-222](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/PlcManager.cpp#L122-L222)）：

- `sendCodeInfo()` 同时通过 S7 DBWrite 和 TCP 文本发送
- `overallSuccess = s7Success || tcpSuccess` — 任一成功即视为成功
- S7 断开时仅记录日志，不阻断 TCP 发送

**设计目的**：

- S7 通道：与 WCSApp 完全兼容，用于 PLC 控制器的直接指令写入
- TCP 通道：用于多 PLC 客户端场景，通过 HP-Socket 群发指令
- 双通道冗余：任一通道成功即可保证指令到达

### 8.3 为什么使用双通道信号处理 PLC 反馈？

**代码位置**：

- 逐条信号: [PlcManager.cpp:621](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/PlcManager.cpp#L621)
- 批量信号: [PlcManager.cpp:665](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/PlcManager.cpp#L665)
- 批量定时器: [PlcManager.cpp:75-81](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/PlcManager.cpp#L75-L81)

| 信号 | 频率 | 用途 | 接收者 |
|---|---|---|---|---|
| `plcFeedbackReceived` | 逐条 | 业务标记（markSorted） | HttpServer |
| `plcFeedbackBatch` | 每 100ms 合并 | UI 日志刷新 | MainWindow |
| `plcSendInfo` | 逐条发送结果 | UI 状态栏显示发送成功/失败 | MainWindow |

**设计目的**：高并发落格场景（如每秒数百条反馈），将 N 条 UI 日志合并为 1 次信号发射，减少主线程事件队列压力。

### 8.4 异常分拣标记（markException）

**代码位置**: [WaveManager.cpp:88-131](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/WaveManager.cpp#L88-L131)

**触发场景**：

### 8.5 TOCTOU 竞态修复（markSorted/markException 中的关键逻辑）

**代码位置**: [WaveManager.cpp:37-86](file:///d:/WCS/WCSApp/WCS_httpServer/WCS_httpServer/WaveManager.cpp#L37-L86)

**问题场景**：多个 PLC 反馈同时到达，同时判定波次完成，导致重复回传。

**修复前（有 bug）**：

```cpp
complete = checkWaveCompleteLocked();  // 锁内检查
unlock();
if (complete) {
    alreadyReported = m_bReported.exchange(true);  // 锁外交换 → TOCTOU!
}
```

**修复后（正确）**：

```cpp
complete = checkWaveCompleteLocked();  // 锁内检查
if (complete) {
    alreadyReported = m_bReported.exchange(true);  // 锁内交换 → 原子化
}
unlock();
```

**数据一致性保障**：`checkWaveCompleteLocked()` 与 `m_bReported.exchange(true)` 在同一个临界区内执行，确保判定和标记不可分割。
