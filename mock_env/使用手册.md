# WCS 窄带分拣 Mock 联调仿真台 — 使用手册

> 配套目录：`D:\WCS\WCSApp\WCS_httpServer\mock_env\`
> 目标：在你自己的电脑上，用仿真软件扮演 **RFID 推送端 / PLC(含S7锁格) / 软件(WMS) 三方**，
> 与真实 `WCS_httpServer.exe` 全链路联调；所有报文（谁收谁发、原文+HEX）都在“报文总览”保留可见。
> 纯 Python 标准库 + tkinter，无第三方依赖。本机 Python 3.14 已验证。

## 一、总体拓扑（全部在本机 127.0.0.1）

```
┌─────────────── 你的电脑 ──────────────────────────────────────────┐
│                                                                   │
│  WCS_httpServer.exe（读 config\http_server.xml → MOCK 地址）        │
│    ● 监听 HTTP 8191  ← 软件下发(H4/H6/H5)                          │
│    ● 监听 TCP 102   ← 仿真PLC客户端连入，收{EPC|格口|小车}并回执     │
│    ● 连出 TCP 2010   → 仿真RFID推送服务（收{SNxxxx|01|EPC}0D帧）     │
│    ● 连出 S7 102     → 仿真PLC S7（读 DB77 25B 锁格位图，1s轮询）    │
│    ● 连出 HTTP 9100  → 仿真RFID查询服务（EPC→SKU）                  │
│    ● 连出 HTTP 8099  → 仿真WMS网关（收H7满箱/H8完结回传并应答）       │
│                                                                   │
│  mock_app.py（本仿真台 GUI，双击 run_mock.bat）                      │
└───────────────────────────────────────────────────────────────────┘
```

| 端口   | 谁监听 | 用途                                            |
| ---- | --- | --------------------------------------------- |
| 8191 | WCS | 软件→WCS 波次/绑定/取消（仿真台作客户端 POST）                 |
| 102  | WCS | PLC→WCS 落格指令/反馈（仿真台作 PLC 客户端；plcListenPort 当前=102） |
| 2010 | 仿真台 | RFID 推送服务端（WCS 自动连入，可看到心跳）                    |
| 102  | 仿真台 | S7 锁格位图 DB77（WCS 1s 轮询，上升沿=满箱锁格→H7）           |
| 9100 | 仿真台 | RFID 查询 /open-api/rfid/query（EPC→barcode=SKU） |
| 8099 | 仿真台 | WMS 网关（接收 H7/H8，按样例应答 success）                |

> 端口以 `mock_env\config_mock\http_server.xml`（mock 模板，可自定义）与
> `release_WcsHttpServer\config\http_server.xml` 当前值为准，上表为当前值。
> ⚠ `plcListenPort` 当前=102，与仿真台 S7(102) 在同一台机器上会互相占用监听，
> 联调建议把 plcListenPort 改为非 102（如 2000）再启用 mock 配置。

## 二、快速开始（3 步）

1. **一键启用 MOCK 配置**（自动备份正式配置，随时可还原）
   双击 `mock_env\启用Mock配置.bat`（或 GUI“配置”页按钮）。
   它会备份 `release_WcsHttpServer\config\http_server.xml` 到
   `config\config_backup\*.bak`，然后写入本机地址配置。

2. **启动 WCS**：双击 `release_WcsHttpServer\WCS_httpServer.exe`
   
   - 等窗口出现后，**点击「开始接收任务」**（不点则软件推送会被拒：HTTP 500“未开始接收任务”）。
   - 之后等波次下发到「已绑定」状态时再点「开始分拣」（场景运行中会提示你点）。
   - 结束后点「结束任务」触发 H8 完结回传（H8 唯一触发方式就是该按钮）。

3. **启动仿真台**：双击 `mock_env\run_mock.bat`（或 `python mock_app.py`）
   
   - 启动后自动运行 5 个服务，顶部状态条显示各通道与 WCS 进程状态；
   - 顶部“状态总览”页可核对全部地址（读自配置文件）。
   - 需要换端口调试（如端口被占用）：先跑 `run_mock.bat check wms=.. plc=.. rfid=.. gw=.. query=..`
     或在 GUI『配置』页看“端口预期参考”对照表，再**手工**修改 `release_WcsHttpServer\config\http_server.xml`
     （脚本/仿真台绝不自动改写配置文件），重启 WCS 生效。S7 端口固定 102。

> 顺序建议：先启动仿真台再启动 WCS（WCS 会自动连入；先启动 WCS 也行，
> RFID/S7/PLC 侧均有自动重连：RFID 3s、S7 心跳 2s、PLC 3s）。

## 四、场景与演练页（一键跑通/练异常）

### 4.1 标准全流程（自动编排，检查点提示人工点 WCS 按钮）

参数：格口数 / 每格SKU / 每SKU件数 / orderCode / 节奏ms。
流程：H6 绑定 → H4 下发 → **[人工:点开始分拣]** → RFID 逐件推送 →
每件等待 WCS→PLC 指令（PLC 自动回执状态1）→ 该格件数到齐后自动 **S7 锁格** →
等 H7 到网关（自动答 success）→ 自动解锁（模拟换箱）→ 全部完成后 **[人工:点结束任务]** →
等 H8 到达并应答。每一步与报文一一对应，结果在“场景日志”和“报文总览”。

### 4.2 异常演练（下拉选择）

- **NOREAD 空读帧**：验证 WCS 只记日志不处理；
- **未映射 EPC**：查询 0 命中 → 3s×2 重试 → 写“SKU查询超时”异常（约12s）；
- **查询延迟 1300ms**：超过“首达→发PLC 1s”窗口 → 拒发、写“发送超时”异常；
- **落格反馈状态码=2**：WCS 按异常处理，不 markSorted；
- **H7 应答失败**：网关答 success=false → WCS Outbox 约 30s 自动重试（观察窗40s，中途把网关切回“成功”可看到重试成功）；
  H8 失败则 5s 一拍快速重试、30s 会话兜底——可手动观察。

## 五、协议要点速查（源码核实 + 实机联调验证）

- **RFID 通道**（WCS 是 TCP 客户端连 2010）：
  - 帧 `{流水号|设备码|EPC}0D`；帧尾现场为**字面 “0D” 两个字符**（ASCII 30 44），仿真默认同款；WCS 按 `}` 分帧，也容忍 CR/CRLF/无帧尾、粘包拆包。
  - 心跳：配置开时 WCS 每 2s 发 `RFID{HEARTBEAT}0D`（字面0D，无回车）。**现场与当前 mock 模板均 rfidHeartbeatEnable=0（关闭）**；想观察心跳通道可临时在 xml 置 1 并重启 WCS。
  - 小车号=流水号数字部分去前导零：SN0027→27，发 PLC 时补 3 位“027”。设备码不参与业务；SN 范围 1~99 无代码校验。
  - WCS 收到帧后立即用 EPC 查 9100（`POST {"epcList":[...]}`，头 `Authorization: <rfidAppkey 整串>`，5s 超时，空结果 3s 后重发共3次），命中即绑定 barcode=SKU；**barcode 必须是当前波次 inco**，否则该件不发送并写异常。
  - **1 秒实时性**：EPC 首次到达→发出 PLC 指令窗口 1000ms，超时拒发写“发送超时”。仿真台查询应答默认即时，自动推送建议节奏 ≥300ms。
  - 缓存：EPC→SKU 300s TTL，5 分钟内重复推同一 EPC 不会重复处理。
- **PLC TCP 通道**（WCS 监听 `plcListenPort`，当前模板=102；PLC 主动连入）：
  - WCS→PLC：`{EPC原文|格口号3位|小车号3位}`，无帧尾、无 ACK 要求；只发格口串首格口。
  - PLC→WCS：仅认 `{start}`、`{stop}`、3字段、5字段反馈。
  - 5字段=`{EPC|格口|首车|尾车|状态}`：状态码**仅 2(无格口)/3(信息不全) 判异常**，1/0/其它按成功；尾车（=小车号+2）**只存档不校验**。3字段 `{EPC|格口|小车}` 无状态=成功。
- **S7 锁格通道**（WCS 连出 102，只读）：
  - WCS 连接后每 1s 读 **DB77 偏移0 共25字节**（200位），**位=格口号**（格口1→bit1，格口66→byte8 bit2），LSB 位序；上升沿=锁格→**禁用该格口并触发 H7**；下降沿=解锁。WCS **从不回写** DB77。
  - 仿真台按此实现（“S7锁格”页点 3 → WCS 日志 `S7锁格检测(上升沿) grid=3 lock` + `格口已禁用 grid=3` + H7 到达网关页）。
- **H7/H8 回传**（WCS→软件网关 8099）：
  - URL = 配置 test URL + `?appkey=<appkey>&method=gwisSubProductClassifyOrder / gwisSubProductClassifyEndOrder`；Header：`Content-Type: application/json` + **`AppKey: <appkey>`**（与 URL 参数同值）。
  - H7 body：`head{orderCode, orderType:"01", warehouseCode, goodsOwner, fromLocation(=该格件明细 sobi/volu), createDate"…:000", createUserCode"admin", createUserName"管理员", detailList[{num:格口号, targetLocation:容器号boxcode, sku:SKU, qty:件数}]}`（按SKU聚合；任一 EPC 未查出 SKU 则整单中止不发）。
  - H8 body：`head{orderCode, orderType:"01", sumLocation:已分拣件数, operuserDate, operuserCode:"admin", operuserName:"管理员"}`。
  - **成功判定只认响应 JSON 顶层 `success==true`**（不校验 HTTP 状态码、body、ts）→ 仿真台一律 HTTP 200 + success 语义。
  - 失败重试：H7 出站 30s×2；H8 5s×3；H8 会话 30s 兜底；均可 GUI“重传H7/H8”补发。
- **WCS 入站应答**：H4 成功 `{"code":"200","message":"successed.","sentTime":"…"}`；H6 `{"code":"200","message":"收到信息"}`；H5 `{"code":"200","message":"取消成功","cancellable":true}`；未点「开始接收任务」→ HTTP 500。**strict 校验：orderQty 必须=ΣgridNumber**；gridNum 限 1~66（越界条目标记异常并跳过）。
- **容器绑定**：latticehole(1~66)→boxcode 单向；满箱禁用后**重绑即恢复**；波次完结(H8成功)后 WCS 清空全部绑定 → 下一波需重新 H6。

## 七、常见问题排查

| 现象                       | 处理                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------- |
| 顶部“WCS进程:未运行”            | 先启动 WCS_httpServer.exe（并确认已启用 MOCK 配置）                                              |
| WMS 下发被 500“未开始接收任务”     | 在 WCS 界面点「开始接收任务」                                                                   |
| RFID 页“无已连接 WCS”         | WCS 启动即自动连 2010（3s 重连）；检查是否启用了 MOCK 配置、2010 未被占用                                    |
| 推了 RFID 帧但 WCS 不发 PLC 指令 | ① 波次须点过「开始分拣」(SORTING)；② EPC 必须在查询页有映射且 SKU 属于当前波次；③ 距首次推送须 ≤1s（查询延迟别开大）；④ 格口未禁用/未锁 |
| H7 没到 WMS 网关             | H7=锁格事件触发：先在「S7锁格」页锁一格口；该格需有分拣记录、已 H6 绑定容器；EPC 全部已查出 SKU                            |
| H8 没到网关                  | H8 只由 WCS「结束任务」按钮触发（无自动完结）                                                          |
| 网关收到请求但提示 ⚠              | 查看 URL/Header 的 appkey 与 method 是否与配置一致（这正是需求11要检查的）                                |
| 场景在某步卡住                  | 看“场景日志/检查点”提示，通常需要你在 WCS 界面点按钮后按「继续」；或「中止场景」                                        |
| WCS 日志出现“上一波次未完成/补发H7H8” | release 数据库残留历史波次所致，属正常；可在 WCS「波次数据记录」面板查看/重传，或按第八节清库                               |
| 端口被占用 / 想换端口调试         | 关闭旧的仿真台；先跑 `run_mock.bat check wms=9191 plc=2500 ...`（或直接启动 `run_mock.bat wms=.. plc=.. rfid=.. gw=.. query=..`），到仿真台『配置』页“端口预期参考”表格核对 期望 vs 配置文件当前值 → 停止 WCS → 手工修改 `release_WcsHttpServer\config\http_server.xml` 对应节点（先备份）→ 重启 WCS 与仿真台。仿真台**绝不自动改写配置**；S7=102 固定 |
| 还原正式环境                   | 双击 `还原正式配置.bat` → 重启 WCS                                                            |

## 八、与现网差异、收尾与注意事项

1. mock 模板 `mock_env\config_mock\http_server.xml` 直接取自你自己维护的配置
   （binding 预绑定 001~065、`plcListenPort`、`rfidHeartbeatEnable`、仓库/货主、appkey、
   method、策略均逐字一致，**可自定义**）；只需保证地址类节点指向本机仿真台：
   RFID 服务端 127.0.0.1:2010、查询 9100、H7/H8 回传 8099、S7 127.0.0.1:102。
   ⚠ `plcListenPort` 若保持 102 会与仿真台 S7(102) 监听互斥，联调建议改为非 102。
2. 一键脚本从不删除文件：正式配置备份在 `release_WcsHttpServer\config\config_backup\*.bak`，可随时还原。
3. 建议在干净的波次状态上跑标准流程；如数据库有历史未完成波次，可在 WCS「波次数据记录」面板用「新任务」清空，或在停止 WCS 后把 `release_WcsHttpServer\data\sorting_records.db*` 移走备份再让 WCS 重建。
4. 自检：`python mock_env\selftest.py`（不需要 WCS）验证仿真台各通道线级行为，期望 17 PASS。
5. 本机可能残留旧 WCS_httpServer 进程（其它会话），若双开被“程序已在运行”拦截，请在任务管理器结束多余实例。

## 十一、现场实机旁路模拟（客户机，不跑物件也能测）

场景：WCS 已连真 RFID/真 PLC，但没有物件可跑，想用 IP/端口在客户机上**注入 RFID 推送、模拟 PLC 落格反馈**。
只需拷贝下面**两个单文件工具**到客户机（需 Python 3，无第三方依赖；GUI 版仿真台亦可，见第三节）：

| 工具 | 角色 | 为什么是这个角色 |
|---|---|---|
| `field_rfid_sender.py` | **TCP 服务端**，监听 `rfidPushServerIp:rfidPushServerPort`（默认 127.0.0.1:2010），等 WCS 连入后推送 `{SNxxxx\|01\|EPC}0D` | WCS 是客户端，主动连 RFID 推送服务端 |
| `field_plc_sim.py` | **TCP 客户端**，连 WCS 的 `plcListenPort`（默认 127.0.0.1:2000），收到 `{EPC\|格口\|小车}` 后回 `{EPC\|格口\|小车\|小车+2\|状态码}` | WCS 是服务端，PLC 作为客户端连入 |

⚠️ **安全第一**：WCS 会把落格指令**广播给所有已连 PLC 客户端（含真 PLC）**。
模拟推送前务必断开真 PLC 的连接或切断机械使能，否则真机会执行落格动作。

### 配置（只改 3 处，且改前备份）
编辑客户机上 WCS 的 `config/http_server.xml`（真机现场的 WCS 配置文件）：
```
<rfidPushServerIp>127.0.0.1</rfidPushServerIp>      ← 原来是真RFID服务端IP；指向本机模拟器
<rfidQueryUrl>http://127.0.0.1:9100/open-api/rfid/query</rfidQueryUrl>   ← 若用假EPC(需在模拟查询页建EPC→SKU映射)；用真EPC可保留现场查询地址
<plcS7Ip>127.0.0.1</plcS7Ip>                          ← 可选：要本地模拟锁格触发H7时改；真S7保留可不动
```
其余（回传 URL/appkey/method/端口）**保持现场原样**，别用本仓库“一键Mock配置”整体替换（那会把 H7/H8 回传也指向本机）。
改完重启 WCS。测试完改回（或保留备份比对）。

### 步骤（真 EPC 场景，推荐）
1. 断开真 PLC 与 WCS 的连接（或断机械使能）；真 RFID 服务端不用停（只是暂时没 WCS 连）。
2. 起工具（两个窗口）：
   `python field_rfid_sender.py`　　　`python field_plc_sim.py`
3. 启动 WCS → 点「开始接收任务」→ 软件下发波次（H4）+ 容器绑定（H6）→ 点「开始分拣」。
4. 在 RFID 窗口输入**现场真实 EPC** 回车 → WCS 查真查询服务 → PLC 窗口出现落格指令并自动回执状态1 → WCS“已分拣 +1”。
   循环输入多条即模拟多件；波次件数满后可在 PLC 页/S7 侧模拟锁格验证 H7（需改 plcS7Ip 用本地 S7 模拟时）。
5. 结束：点「结束任务」验证 H8 后，还原配置。

### 无真实 EPC 时的做法
在 RFID 窗口输入假 EPC 前，把 `rfidQueryUrl` 指向本机模拟查询服务（GUI 版仿真台“RFID查询服务”页或自行起 9100 服务），并在映射表把该 EPC 映射为**波次明细中真实存在的 SKU**，
否则 WCS 查不到 SKU 不会发指令（会写“SKU查询超时/不在格口”异常）。

### 仿真机与 WCS 异机（WCS 与真 PLC 的 IP 不同，仿真台单独一台电脑）
GUI 版仿真台默认全部走 127.0.0.1（同机回环）。跨机注入时给仿真台两个网络参数：

- 仿真机（运行 `run_mock.bat`）：
  - `run_mock.bat wcs=<WCS机IP> bind=0.0.0.0` —— `wcs=` 让“PLC客户端/软件下发(WMS)”两个出站
    通道连到 WCS 机；`bind=0.0.0.0` 让 RFID推送服务端/S7/网关/查询 等监听服务对外可达。
  - 首次监听 0.0.0.0 时 Windows 防火墙弹窗请选“允许”（专用/域网络）。
- WCS 机：改 `config\http_server.xml`（先备份，测完还原；真 PLC 通道不在此列，无需动）：
  - `<rfidPushServerIp>` 与 `<rfidQueryUrl>` → 仿真机 IP（端口 2010 / 9100）
  - 需要收 H7/H8 或 S7 锁格时：`feedbackTestUrl/feedbackEndTestUrl` → 仿真机 IP:8099、
    `<plcS7Ip>` → 仿真机 IP
  - 改完**重启 WCS_httpServer.exe**；WCS 会主动连入仿真机对应服务。
- 效果：仿真机页面推 RFID 帧/WMS 下发(H4/H6) 即发到 WCS；真 PLC 连接不受影响。
  若还要注入“PLC 落格反馈”，需先断开真 PLC（WCS 会把落格指令广播给所有已连 PLC 客户端，见上⚠）。

### 真 PLC 收到指令却不执行/不回执时（仿真台只注入，真 PLC 负责落格）
先分清“指令发给了谁”：仿真台 PLC 页能看到 `{EPC|格口|小车}` 只证明**仿真台自己的 PLC 客户端**
连着 WCS；真 PLC 是否收到要看 WCS/真 PLC 侧。按序排查：

1. **让仿真台退出 PLC 角色**：启动时加 `noplc nos7 nogw noquery`（只留 RFID 推送服务端），
   如 `run_mock.bat wcs=<WCS机IP> bind=0.0.0.0 noplc nos7 nogw noquery`；
   之后仿真台 PLC 页不再显示指令 → 再看指令是否仍产生、真 PLC 是否动作。
2. **真 PLC 是否还连着 WCS**：改过 `plcListenPort`（如 2000↔102）或换过配置后必须重启 WCS；
   真 PLC 侧配置的“WCS IP/端口”要与 WCS 当前 `plcListenPort` 一致（PLC 是 TCP 客户端连入 WCS）。
   在 WCS 界面/日志确认 PLC 连接数 ≥1。
3. **WCS 已把指令发给 PLC 客户端吗**：仿真台（noplc 时看不到）改看 WCS 日志 `PLC\PLC.log`
   或真 PLC 侧接收日志；没有输出=WCS 侧被状态机拦截（波次未「开始分拣」/EPC 的 SKU 不在波次/
   格口禁用/超 1s 窗口等），与真 PLC 无关。
4. **物理在位条件**：多数分拣机 PLC 要“指令里的车/格口与 PLC 现场跟踪一致”才落格。
   纯注入的车号（SN 推出来的小车号）若没有真实小车/物件在读码站经过，PLC 会忽略指令——
   用真实物件+真实读码器过一遍对照；或注入与现场实际经过车一致的车号帧。
5. **回执**：落格后真 PLC 回 5 字段 `{EPC|格口|小车|小车+2|状态}`，WCS 才记“已分拣”；
   仿真台不要开“自动回执”（其 PLC 通道已停用则不参与）。

### 现场小坑
- 反馈状态码仅 2(无格口)/3(信息不全) 判异常，其余按成功；第4字段(小车+2)不校验，可按 `PLC> ` 输入 `s2`/`s3` 演练异常回执。
- 想练“查询延迟/1s窗口拒发”：在模拟查询服务加延迟 >1000ms 即可看到 WCS 写“发送超时”。
- 手动模式 `python field_plc_sim.py --manual`：每条指令后按回车才回执，便于逐步观察。
- 断线重连：PLC 工具每 2s 自动重连；RFID 端 WCS 断开后约 3s 自动重连，两边无需人工干预。
- 无 Python 的机器可用 GUI 版仿真台对应页（需整套 mock_env）或 PowerShell 直连发帧（PLC 反馈可直接用
  `New-Object Net.Sockets.TcpClient` 发送同格式字符串；RFID 因 WCS 是客户端，仍需先起一个 TCP 服务端等 WCS 连入）。
